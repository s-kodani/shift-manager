### 2.1 役割先行の品質比較の例

役割不足が1→0、一般業務不足が1→2となる案は、役割先行の評価では改善となり得る。一般業務不足だけで「品質悪化」と判定すると、選択された優先順位と食い違う。

修正後は同じ入力・方式・重み・優先順で比較し、先行評価を保護する。一般不足と役割不足は個別にも示す。時間制限で最適性未証明なら、その状態を保持する。

## 3. 一致を確認した主要方針

| 方針 | 照合結果 |
| --- | --- |
| 勤務ルールの階層 | 共通・雇用区分・個人をすべて満たし、個人設定で共通を緩めない |
| 月最低勤務時間・日数 | 必須条件。勤務不可・休暇で達成不能でも自動で下げない |
| 不足の扱い | 一般業務・役割の不足は表示し、勤務条件違反と区別 |
| 時間集計 | 休憩は除外。研修・会議・準備・移動は勤務時間に算入し、通常処理能力には算入しない |
| 60分と30分 | 業務選択は標準60分、稼働・需要充足は30分。前後半の不足を相殺しない |
| 需要 | 能力換算人数。直接入力優先、算出値は参考。0と未入力は区別する設計案 |
| 休憩・切替 | 自動休憩は連続取得。業務ペア別準備。休憩前後の同一業務の継続では休憩を除く |
| 役割 | 最低人数と比率の大きい方。比率は稼働実人数。業務別は当該業務処理者だけ |
| 公開後 | 承認等による勤務取消を反映し、残る勤務・出退勤・公開済み休憩を維持 |
| 固定 | 明示固定だけ維持。固定勤務の休暇承認は管理者の明示解除後 |
| 計算状態 | 有効案・最適性未証明・未発見・実行不可能・失敗を区別 |
| 初期版機能 | 人数算出3業務、Excel、AI-02は本開発で完成させるv1.0範囲 |
| AI責任 | 計算・判定は数理最適化と通常処理。AIは根拠の説明・比較。自動公開・承認はしない |
| 通知・承認 | アプリ内通知、チーム管理者の休暇承認、作成管理者の直接公開 |
| 開発期間 | MVP12〜16週、本開発追加16〜24週、全体約7〜10か月という仮定は整合 |

期間・人数・応答時間を達成したという確認ではない。500人性能、現場の作業効果、AIの説明品質は今後の実測対象である。

## 4. 残る未決事項

以下は今回のレビューで任意に決めていない。テスト戦略書第14章のTD-01〜14を共通の決定一覧とし、該当実装前に期待値を確定する。

| 論点 | 参照 | 主な影響 |
| --- | --- | --- |
| 実ルール値、勤務日・休日の定義、前後月の履歴不足 | TD-01 | 月下限、週上限、連続勤務の正解 |
| 休憩の閾値・取得範囲、実労働時間基準での算定整合 | TD-02 | 休憩量と集計時間が相互に関係する場合の算定手順 |

| 希望優先の順序、役割不足の尺度、業務別設定の合成 | TD-05 | 目的関数、先行値の保護、比較の合否 |
| 取消単位、一部休暇、欠勤操作、月下限矛盾時の承認・反映 | TD-06 | 公開後の取消と再配置の整合 |

特に月下限を満たせなくなる休暇の承認時は、警告・設定調整・勤務取消・公開版への反映順を確定する必要がある。勤務ルールを自動で緩めることや、違反案の公開を許すことは今回の修正に含めない。
