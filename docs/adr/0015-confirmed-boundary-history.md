# ADR 0015: 確認済みの月境界勤務履歴と入力版

日付: 2026-10-11。状態: 限定実装・ローカル検証済み。対象: WP-02／03／05、Q81／98、TS-RULE-06／TS-NEW-05。確定製品仕様の変更なし。

## 判断

管理者が確認した月外の勤務分を、スタッフ・日付・確認根拠・変更者・企業入力版と結び付ける。休日は明示した0分であり、未入力日の0補完は行わない。休憩・取消を除き、研修・会議・準備・移動を含める。入力事実の確認と勤務案全体の独立検証は別の状態である。

`work_history_operation`と`work_history_version`を追加し、企業revision更新・複数日の事実・監査を同じD1 batchで保存する。SQL内でも現在の権限・初回変更済み・対象チーム・期待版を照合する。訂正は新しい版を追記し、以前の事実を更新・削除しない。同操作IDは同じ内容だけ再送可能で、権限失効後の再送は拒否する。

対象月の前後31日以内を入力対象とする。これは現行入力契約の連続勤務上限31日を満たすための実装範囲であり、製品仕様の保存期間ではない。対象月内の勤務を月外履歴として投入しない。1操作500行までの分割登録とし、サービスの性能上限と主張しない。

凍結時は企業設定と各スタッフの全ルールから必要前月日を導出する。必要日数は週境界の日数と各連続勤務上限の最大値。翌月は既存の数理モデルに合わせ、最後の週・連続勤務上限の範囲で確認済みの事実だけを参照する。翌月未確定日を欠損扱いや休日扱いにしない。入力へは勤務分だけを渡し、参照した履歴操作・日付・版をlineageへ保存する。

履歴表示は、理由付き全面固定と勤務不可が重なる登録条件でも現在の固定を参照する。履歴変更は企業入力版を進め、以前の案を古い入力として扱う。旧R2入力は変更しない。

## 代替・検証・限界

欠損を0にする代替はQ81／98に反するため採用しない。クライアントがVERIFIEDを送る方式も採用せず、確認根拠を保存した後にOR-Toolsと独立チェッカーで案を再検証する。

既存の[D1 batch仕様](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)に沿って、版競合・途中の権限失効・最後の監査失敗をローカルD1へ注入し、部分登録とrevision更新が残らないことを確認した。履歴入力の記録（過去の私有資料・公開対象外）を参照。

公開済み勤務からの自動履歴生成、取消との同期、公開済み対象月の再検証、通知・公開の原子更新は後続工程。履歴が全て揃った案でも、この段階の製品APIはBLOCKED_A1を維持する。今回のCloudflare配備・大規模性能・現場受入は別途検証する。
