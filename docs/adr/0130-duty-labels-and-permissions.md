# ADR 0130: 対応可能な担当・担当区分・権限の表記を区別する

2026-10-17。ユーザー指定により、アプリ内の「役割」を文脈別の表記へ統一する。

## 決定

| 文脈 | 画面表記 | 意味 |
| --- | --- | --- |
| スタッフ設定・取り込み・変更履歴の `roleIds` | 対応可能な担当 | 本人が担当できるSV・リーダーなど。複数選択できる |
| チームで登録する種類・シフト配置の `roles` / `roleId` | 担当区分 | その時間に担うSV・リーダーなど。同時に配置・計数できる区分は1つ |
| 必要人数・比率・不足・評価順序 | 担当区分の条件／担当区分の必要人数／担当区分先行 | 担当区分ごとの配置条件と計算結果 |
| 企業管理者・チーム管理者・スタッフのアクセス制御 | 権限 | 参照・編集・承認・公開などの操作範囲 |

スタッフ管理のカード名・保存ボタン、チーム設定、需要管理の個別／一括入力、シフト編集、公開・取消の不足確認、公開不可理由、設定ヘルプ、CSVの説明、入力変更履歴、検証結果の説明へ適用する。ヘルプでも対応可能な担当と権限が別設定であることを説明する。

## 維持する仕様

表示名の変更に限定する。APIキー・DB・CSVの `role_ids`・保存済みID・権限モデルは変更しない。SV・リーダーの配置適格性、一般業務との兼任可否、最低人数と比率の最大値、企業端数処理、比率の分母、同時計数の制約、評価順序、独立検証、公開・取消判定も維持する（Q61〜Q63・Q76〜Q78・Q111・Q120・Q122）。

数理モデル・過去のQ&A・実施済み証跡で使っている技術用語「役割」は保持する。各正本文書から本決定へ参照し、画面上の語と対応付ける。

## 検証

型チェック・クライアントテスト・関連統合テスト・ビルドと、架空データによるスタッフ設定／需要管理／シフト編集のブラウザー確認を行う。結果と未実施範囲（過去の私有資料・公開対象外）に記録する。初回はローカル検証までとし、その後の追加依頼「反映して」によりCloudflareへ1回配備した。対象・上限・検証範囲は同じ結果文書に記録する。
