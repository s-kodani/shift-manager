# ADR 0016: 再検証した公開版と監査・通知の原子保存

日付: 2026-10-11。対象: WP-07、Q12・24・70・81・82・98・102・118。製品仕様の変更ではない。

## 採用した実装

公開は管理者の明示操作とする。クライアントから検証結果や配置を受け取らず、指定した成功ジョブまたは最新の編集headの不変R2オブジェクトを取得する。現在の入力版・編集版・公開版を照合し、チームのContainer排他で独立チェッカーを再実行する。プロセス停止確認と入力ハッシュ一致まで成功として返さない。

VERIFIED、違反なし、欠損履歴なしを要求する。検証結果の必要人数・役割不足も必須フィールドとし、欠損を0とみなさない。通常の不足は管理者の明示確認で公開できる。履歴不足や必須違反を確認チェックで迂回できない。

R2へ別名で不変の公開証跡を書き、D1の単一batchで公開版、全スタッフ×暦月の日別勤務、通知イベント、有効なチーム所属者の個別受信箱、監査、最終commitを保存する。SQLトリガーで入力・編集・公開版・生きた管理権限・完全な件数を検査する。最終commitだけがheadと企業revisionを進める。途中のSQL失敗は全体を戻す。0行更新をSQL失敗と仮定しない。[D1 batchの仕様](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)。

公開時の入力revision Rと、公開を適用した企業revision R+1を分離して保存する。古い凍結入力・ジョブ・編集案の再採用を入力版で止め、次の凍結入力は最新の公開勤務を参照したreallocationとする。時刻・休憩・休日は変えず、業務配置だけを再計算する。明示固定の範囲や勤務不可例外を勝手に増やさない。

隣接月の公開勤務は確認済み境界履歴の優先参照元とする。公開版を手入力の勤務履歴で上書きしない。手入力の履歴と公開版参照を別のsource・版として記録する。

公開版・勤務事実・イベントはcommit後に追加・変更・削除できない。個別通知は本人だけ既読へ一度変更できる。R2/D1間は分散トランザクションではなく、不確かな失敗のR2オブジェクトは削除しない。猶予期間後に未参照を証明するGCは別作業。

## 代替案と理由

計算完了時の直接公開はQ24の明示操作と独立再検証を満たさない。既存結果のVERIFIED表示だけで公開する案も、入力・編集変更の競合を取り逃がす。公開状態をR2だけで切り替える案は監査・個別通知との原子性がない。別の公開版だけを更新して企業revisionを変えない案にはジョブ・入力・編集への追加フェンスが必要なため、既存の企業revisionも進める構成を採用した。

## 実施結果と限界

実施記録（過去の私有資料・公開対象外）にD1/R2の競合・全体ロールバック、実Dockerの再検証・再配置・再公開、管理者／スタッフの画面、CSVを記録した。実Containerで見つけたdraft専用の結果型を修正し、reallocationも入力との完全一致を要求する。検証中の開発Worker再読込は同じジョブの旧プロセスを停止して試行2で回復した。

企業revisionが公開の適用版と異なる場合は保守的に再検証待ちを表示する。Q118の適用開始月に該当する全公開月を自動再検証して結果版を保存する処理は未実装。このフラグを再検証済みと扱わない。取消確定・参加解除・公開版への即時反映、Cloudflareの累積配備・障害試験、大規模の公開batch/画面性能、現場受入も残る。
