# ADR 0051: 同じ計算内の内容に結び付いた内部検査証明

日付: 2026-10-12。状態: 実装・ローカル検証。Cloudflare互換性・性能目標・MVP全受入は別判定。

## 問題と判断

資源制限付き試験（過去の私有資料・公開対象外）で500人のexecuteJobは141,843／145,383ms、150秒期限まで最少4,617msだった。初期案の独立検査を済ませ、後続探索がUNKNOWNでその案を保持した場合も、内部finalCheckは11.26〜12.09秒を使って同じ案を再検査していた。保存前の別HTTP独立チェッカーは必要なまま、同じ計算内の重複を減らす。

1回のsolve呼出しが所有する1件の`CandidateCertificate`を導入する。入力全体・配置全体を丸めずにJSON化し、SHA256とVERIFIED証明を保持する。CPから得た目的ベクトルとチェッカーの値が一致し、検査前後の内容が同じ場合だけ保持する。初期CP実行可能性の確認は毎回実チェッカーを呼び、未確認の保存候補の事前検査をこの証明へ転用しない。

0の段階証明と内部最終検査は、入力・配置の内容と目的ベクトルが一致する場合だけ再利用する。企業・チーム・版・履歴・希望・固定・例外・分単位区間を含む全入力を対象とする。同じオブジェクトをその場で変更しても一致しない。辞書のキー順だけが変わった場合は同じ内容として扱う。返却した報告の変更が保存済み証明を汚染しないように報告をコピーする。INVALID・HISTORY_UNVERIFIED・目的不一致は保持しない。

別solve、HTTP `/check`、保存・公開・手動変更・取消の検査へキャッシュを共有しない。`compute-execution.ts`は従来どおり別HTTP `/check`の応答でソルバー内の証明を置き換え、D1の版・権限・期限・原子更新を照合する。改変した配置は、内部再利用の直後でも実HTTP `/check`でINVALIDになることを確認する。

## 代替案と限界

オブジェクト同一性だけの判定は、その場での変更を検出できないため採らない。判定項目の一部だけをハッシュする方式は古い入力や例外を見落とすため採らない。処理間で永続化する方式は、チェッカー版や失効状態の寿命を別途管理する必要があり、今回は採らない。

内容のJSON化・SHA・報告コピーには時間・メモリがかかる。新しい配置が得られた場合は再利用できず、新規の全検査を行う。VERIFIEDは最適性証明ではなく、UNKNOWNの探索をOPTIMALへ変更しない。全候補・目的段階・120秒予算・150秒期限と必須条件を維持する。

証明が管理する検査の呼出回数・再利用回数・内容照合時間と、最終検査のEXECUTED／REUSED_VERIFIED／NOT_RUNをmetricsへ分けて返す。保存候補の事前検査は既存のsavedCandidate.precheckSecondsで別に記録する。実施結果（過去の私有資料・公開対象外）に実装・実測・未検証事項を分離する。定期backup有効化保留・30日保管・通常メールdisabled・Cloudflare最終一括を維持する。
