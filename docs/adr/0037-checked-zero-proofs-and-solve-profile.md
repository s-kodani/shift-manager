# ADR 0037: 検証済み0の段階証明と通常計算プロファイル

2026-10-12。状態: 実装・限定検証・PoC通常ジョブへ採用。G0／MVP全受入は未完了。製品要件・候補集合・段階順序を維持する。実行結果と採用範囲は実施記録（過去の私有資料・公開対象外）を参照する。

## 判断

`balanced-incumbent-v4`はv3の区間別ヒント・適格な単一役割の同点選択に、初期探索の予算配分と非負0の証明を加える。旧方式は比較用に残す。初期限定探索へ総予算の25%と、構築・既存の最終検査余白を除いた残時間の半分の小さい方を割り当てる。限定探索の解なし・最適を元問題の判定へ流用しない。

役割先行不足、一般／同段階役割不足、未充足希望件数、余剰は、非負整数の項を非負係数で足した目的で下限0を持つ。独立チェッカーが必須条件をVERIFIEDとし、全段階の評価ベクトルがモデルと一致した案で、その段階が0なら元問題の下限へ到達した証明になる。上位の全段階が証明済みの場合に限り、`OPTIMAL`・`solverInvoked:false`・`NONNEGATIVE_ZERO`を記録して次へ進む。現在の案が変われば独立チェックを再実行する。

上位が未証明の場合はこの省略を行わず、後段の通常探索が上位の実値を改善できる余地を残す。既存の上位実値の保護境界、全候補、最終独立チェックを維持する。正の評価・時間切れ・履歴不足・チェック不一致を0の証明にしない。全体OPTIMALは全段階の証明がある場合だけとし、一部0でも後段が未証明ならFEASIBLEのまま。

## 通常ジョブへの接続

通常`/solve`へ内部ヘッダー`X-Optimizer-Profile: mvp-joint-v1`を追加すると、固定のv4／120秒を使用する。任意の方式・時間は受け付けない。ヘッダーなしの従来20秒と単一業務PoCは互換性のため残す。Workerの`OPTIMIZER_SOLVE_PROFILE`で選び、利用者のHTTP入力から選択させない。`/check`へはヘッダーを付けない。

通常ジョブは結果の`calculationProfile`・`metrics.initialHintStrategy`・`metrics.budgetSeconds`を設定と照合する。別設定・旧runtimeの返答は独立チェックと保存の前に拒否する。結果に方式と予算を保持し、ジョブ・入力版・保存SHAと結び付ける。Workerの150秒通信期限・D1の180秒実行lease、standard-2／最大1、構築100万変数ガード、保存／展開上限は変更しない。Queues・別チェック・R2/D1・停止の実測を、私有benchmarkやローカル成功と区別する。

## 代替案と受入

すべての0をCP-SATで再証明する案は従来方式として比較する。単一の巨大重み、候補削減、未検証のgreedy案の保存、限定探索の最適性流用、探索へ300秒すべてを与える案は採用しない。

小規模正解比較、上位未証明の反例、独立チェックの拒否・ベクトル不一致、正の後段の時間切れ、全0の全体証明、通常設定不一致拒否、実Linux HTTPを検証する。500人の反復・別条件の品質／資源、操作開始から表示までの5分、G0〜G2・現場受入は別途。定期バックアップはユーザー指示で有効化保留、復旧コピー30日、Resend実配送disabledを維持する。
