# ADR 0004: 勤務候補間で共有する日別業務状態

日付: 2026-10-10。状態: A1の実装方式を改善して検証中。OR-Toolsの最終採用、G0合格、101／500人の受入達成は未判定。製品仕様は変更しない。

## 問題と判断

初期の複数業務モデルは、勤務パターン・休憩候補ごとに業務、切替、継続量、実処理、役割の変数を作っていた。同じスタッフ・日に選ぶ勤務は1つなのに、選ばない候補のためにも変数を複製していた。基本負荷の101人では20秒で案を取得できず、500人では100万変数の構築ガードへ達した。

勤務候補の選択変数は維持し、スタッフ・日・配置枠の論理業務を共有する。稼働区間は選択された勤務候補のマスクから求める。区間が同じ実稼働フラグ・業務稼働フラグ・準備除外後の処理フラグを共有する。業務1つは定数、2つは真偽値とその否定、3つ以上はexactly-oneで表す。入力契約と独立チェッカーは変更しない。

これは候補の間引き、段階計算、必須条件の省略ではない。勤務候補を選んでから業務を解く方式は引き続き代替候補であり、採用する場合には配置不能から勤務へ戻す仕組みが必要。

共有後も、初期案なしでは101人／500人・60分枠を120秒で解けなかった。各日の最初の勤務候補と最初の適格業務から作る部分的な探索ヒントをCP-SATへ渡す。ヒントは月上限等に違反することもあり、モデルの制約に固定しない。探索・修正・別候補への変更を認め、ソルバーが返す案だけを独立検証して結果へ載せる。ヒント自体を検証済み案、保存可能な案、最適性の証拠にはしない。後段には従来どおりソルバーの解をヒントとして渡す。

## 表現の対応と境界

- 全休憩候補・出退勤・予定・取消・準備終了・役割必要区間の境界を維持する。準備は整数分で、30分へ丸めない。
- 完全に休憩・予定・取消で占める枠は、直前の論理業務を内部で引き継ぐ。出力には稼働を含む枠だけを載せる。内部状態を架空の勤務配置として出力しない。
- 選ばれた勤務でそれ以前に実稼働がある場合だけ切替・準備を発生させる。開始前の別候補の稼働区間は初回準備の根拠にならない。
- 切替は配置枠の開始で、必要な準備全体が連続稼働に入る場合だけ認める。準備0分の切替にも枠開始の条件を適用する。
- 継続量には選ばれた勤務の稼働分だけを加える。休憩・研修・会議を除外し、準備は切替先へ算入する。枠内の休憩位置に応じた実稼働分を維持する。
- 役割は準備を除いた一般業務の処理区間に割り当てる。共有した論理業務が非稼働なら処理・能力・役割も0になる。

候補単位の有効な業務列は、選択候補の非稼働枠へ直前の業務状態を補うことで共有状態へ写せる。先頭は初回業務、末尾は最後の業務を補う。逆に共有状態から選択候補の稼働枠だけを出力すれば、休憩・予定を挟む継続と切替の評価を保てる。この対応を小規模全列挙と独立チェッカーで確認する。全設定の形式証明やG0の独立レビューを完了したという主張ではない。

## 検証と残る事項

30／60分、希望／充足優先、先頭・全枠の予定中断、複数パターン、全30分休憩位置、2業務／管理専任を含む3業務を独立列挙する。モデルの候補生成を使わず、1分チェッカーが認める全案の最良目的ベクトルと比較する。別候補の早い開始が初回準備を発生させないことも検査する。

実測と試験結果（過去の私有資料・公開対象外）に、構築・探索・検証・最大RSS・人数・期限を区別して記録する。係数精度、希少役割・予定・固定の高負荷、Cloudflare更新版、通常操作から表示までの5分目標、候補範囲と手動編集の完全性は引き続き検証対象。結果の公開ガードは `BLOCKED_A1` のまま。
