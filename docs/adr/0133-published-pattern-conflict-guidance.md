# ADR 0133: 公開後の勤務パターン変更の衝突と復旧案内

2026-10-18。Q69・Q92の公開後の出退勤・休憩維持と、Q83・Q110の全時間参加を変更しない。

## 問題と判断

公開時に固定休憩だった勤務パターンを同じ対象月で自動休憩へ変更すると、公開勤務の休憩種別と現在のパターンが一致しない。従来の準備チェックはこの衝突も`EVENT_ATTENDANCE_CONFLICT`で表示し、需要・予定の修正へ案内していた。研修・会議がなくても発生するため、原因と修正先が誤っていた。また、整合性エラーで勤務履歴の確認まで止まり、登録済みでも汎用的な未確認表示になっていた。

共有の入力検証に`PUBLISHED_PATTERN_CONFLICT`を追加する。公開勤務の出退勤・休憩種別、固定休憩の区間と現在の勤務パターンの不一致を検出し、対象月のパターンを公開時の設定へ戻すことと、新しい設定を翌月以降へ適用することを案内する。準備チェックの修正先はチーム設定にする。パターン削除は従来の`PUBLISHED_PATTERN_MISSING`を維持する。勤務パターン以外の設定変更は従来どおり検証する。

入力を組み立てられた場合、必要な勤務履歴の登録状況を先に照合し、その後で既知の整合性を検証する。整合性のエラーが履歴不足を意味する表示にはしない。組み立てられない場合は、他の未登録・要修正項目の確認を案内する。権限・入力版・編集版の前後照合と読取専用の準備チェックを維持する。

## 復旧と制限

同じ対象月のパターンを公開時の設定へ戻すと、公開勤務を維持した業務再配置へ進める。明示固定の解除で公開済み休憩を動かす、古い案を削除する、休憩の種類を自動変換する回避は行わない。未公開・明示固定なしの計算済み案は新しい設定で再計算できる。公開後に休憩を再設計する機能は追加しない。

## 検証

実施記録（過去の私有資料・公開対象外）。設定変更の拒否分類、設定復元後の再計算入力、公開版と出退勤・休憩の保持、履歴照合、未公開案の再計算をローカルで検証した。ユーザーの追加依頼でWorkerと資産をCloudflareへ反映し、bundle・資産の一致、認証境界、復旧済み対象月の準備完了を確認した。衝突を再現する実設定変更・遠隔シフト計算・再公開は行っていない。
