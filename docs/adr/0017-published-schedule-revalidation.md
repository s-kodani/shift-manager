# ADR 0017: 適用条件が変わった公開済み勤務を独立再検証する

2026-10-11。実装判断。Q118・Q81・Q98、TS-NEW-17／TS-API-05。確定製品仕様は変更しない。

## 採用した構成

企業revisionだけの保守的な「再検証待ち」表示から、企業・チーム・対象月・公開版ごとの検証headへ移行する。公開版の当時の条件・判定・配置は不変のまま、再検証の凍結入力、試行、証明、採用された判定を別に保存する。

勤務ルール・契約・チーム設定は適用開始月を参照し、その月で実際に選ばれる設定版が変わる公開月を対象にする。適用月が後の既存版に覆われる月は、新しいrevisionの過去月設定で無効化しない。雇用区分の条件は対象月の個人契約がその区分を選ぶチームだけを対象にする。計画／個人月入力は指定月だけ。カレンダーは対象月に選ばれる版、確認済み履歴は前後31日以内の月外履歴、隣接月の公開は同チームの境界履歴の変更として扱う。カレンダーの締切のみの変更や参照しない境界日などは、範囲内で保守的に再検証する。

DB triggerが設定／履歴保存のトランザクション内で検証watermarkと配送待ち依頼を保存する。入力保存が途中失敗した場合は依頼も残らない。公開時のhookは公開head更新に置く。複数のAFTER commit triggerの実行順には依存しない。新公開版自身は公開直前の証明を初期判定とし、隣接月に依頼を記録する。既存公開版は0015の初回適用時に一度再検証を要求する。

## 実行・採用

既存Queuesとチーム単位のOptimizerContainerを使用する。通常計算／手動チェック／自動再検証のRPCとプロセスを排他制御する。サービスはクライアントの条件・オブジェクトキー・版を受けず、DBに記録された企業・チーム・依頼IDから公開版を解決する。入力版は実行時の最新企業revisionで凍結し、公開版自身の固定・理由付き例外を使う。未公開編集の例外を流用しない。ソルバーは起動せず、保存済み配置を独立`/check`へ渡す。

事前の登録検査と独立配置検査を分離する。再検証では将来配置の可能性を探す登録検査を証明として使わず、現在公開されている配置をそのまま検査する。型・参照・契約の組立自体が成立しない場合は`INPUT_INVALID`、チェッカー結果は`VERIFIED`／`HISTORY_UNVERIFIED`／`INVALID`、通信／証明／停止の障害は処理失敗とする。完全な検証済み証明には履歴・一般不足・役割不足の指標が必要で、欠損を0扱いしない。早期の配置形状拒否は不足指標を作り足さない。

停止確認後に結果を保存する。D1最終書込の時点で、公開版・対象watermark・実際の検証入力revisionが一致した証明だけをheadに採用する。関係のない企業revision変更でも検査中に変わった場合は、古い証明を保持して同じ依頼の次試行へ進む。適用条件／公開版が置換された場合は旧依頼をsupersededにする。公開勤務や時刻・休憩はこの処理で更新しない。

R2の凍結元資料／組立入力／完全な証明とD1 manifestを結び付ける。入力組立失敗時も、取得できた元資料の版を保存する。不確かなDB失敗の直後にオブジェクトを削除しない。GCは猶予と非参照証明を含む後続課題。依頼・試行結果と操作ID付き再試行記録は保持する。

配送失敗は入力保存を取り消さず、DB配送待ちからCronで再送する。処理失敗は自動で最大3試行、以降は管理者が入力版・対象版・試行を指定して再試行する。停止未確認のRPCは永続フェンスを残す。次RPCは旧プロセス停止を確認して中断試行を記録してから回復する。lease期限だけで実行中プロセスを奪わない。失敗・古い結果・再送で通知や公開版は増やさない。

## 権限と表示

条件保存時の管理者権限は従来どおりトランザクション内で検査する。その後の自動再検証は内部サービスによる読取・検査で、最初に保存した担当者の現時点の所属には依存させない。担当者失効後も公開済み勤務の検査を止めないためである。証明の参照と再試行は現在の対象チーム管理者だけが可能で、R2読取後も権限を再照合する。スタッフへは本人の公開勤務と検証状態だけを返し、他人の違反・履歴・入力版・証明を返さない。

画面は現在の判定、適用対象版と実検証版、直近100件の当時判定を分ける。処理失敗と必須違反・履歴不足を区別し、旧記録が現在の判定かどうかを表示する。待機／実行中だけ状態をポーリングする。新しい公開操作も従来どおり現在の配置を独立再検証し、既知の違反・未検証案を公開しない。

## 代替案と根拠

全企業revisionで全公開月を再検証すると、未来月設定・権限変更などでも過去月が無効になる。保存時に同期コンテナ検査すると、処理待ち・障害を入力保存へ持ち込む。登録検査だけの認定や公開時刻の自動修正は確定仕様を満たさない。DB outbox＋独立チェックを選んだ。

Cloudflareの[D1 batchの原子性](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)と[QueuesのACK・再送](https://developers.cloudflare.com/queues/configuration/batching-retries/)を確認し、実D1/R2で動作を試験した。文書の保証だけを実試験の代わりにしていない。実施結果（過去の私有資料・公開対象外）に制御transportと実Container、未検証事項を分けて記録する。
