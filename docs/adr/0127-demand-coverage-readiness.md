# ADR 0127: 企業共通の曜日・時間帯を使う需要登録範囲の警告

2026-10-20変更：[ADR 0135](0135-schedule-workspace-details.md)により準備チェックを独立画面へ移し、全項目を展開する。古い案の差分は見出し右横のinfoから参照する。以下の従来配置・折りたたみの記述は当時の記録として扱う。

2026-10-16。ユーザー確認済み。「企業の設定で定める営業日と営業時間帯」は、現行の「企業共通の勤務可能曜日・時間帯」を照合元とする。

## 決定

対象月の企業共通勤務可能曜日に該当する日付について、共通時間帯と重なる30分／60分の配置枠と、チームの全一般業務の組み合わせを需要の必要登録範囲とする。需要を設定できない専任業務は含めない。60分枠に対して開始・終了が30分境界の場合、共通時間帯と一部でも重なる時刻基準の枠を含める。雇用区分・個人契約や勤務パターンで照合範囲を狭めない。独立した営業日カレンダーや祝日・臨時休業の設定は追加しない。

2026-10-18修正：保存済み契約の曜日は[ADR 0006](0006-versioned-inputs-and-r2-snapshots.md)のとおり日曜0〜土曜6で照合する。ソルバー用の月曜0への変換を準備チェックに適用し、対象曜日が1日ずれていた不具合を修正した。

直接必要人数が設定済みなら0人も登録済みとする。直接入力が未設定でも算出値があれば、0を含め登録済みとする。直接入力と算出値の優先順位は従来どおり。範囲外の日付・時間帯の行や別業務の行で未登録枠を補わない。

需要・予定の保存有無と既知の入力検査に加えて範囲を照合する。1枠でも欠ける場合は準備項目を完了とせず、`warning`／`DEMAND_COVERAGE_MISSING`とする。画面には未登録総数と日付・時間帯・業務の例（先頭12件）、需要管理への修正ボタンを表示し、完了項目の件数に含めない。全枠が入力済みなら完了とする。

警告だけでは新規計算を停止しない。需要・予定の未保存、入力不正、既知の矛盾、読取・版・権限エラーによる停止は維持する。警告があっても入力全体の整合性・履歴チェックを続ける。未入力枠を自動で0人として保存せず、計算モデル・独立検証・公開条件は変更しない。

## 実装・検証

読み取り専用の準備APIに照合を追加し、取得した対象月に有効な企業ルールとチーム配置枠を使用する。DB migration、追加のクエリ、スナップショット・ジョブ・ソルバー起動は不要。応答契約上も警告は需要登録範囲の警告に限定し、ほかの必須項目の欠落を警告へ変換しない。

ローカル検証（過去の私有資料・公開対象外）とCloudflare反映・確認範囲（過去の私有資料・公開対象外）を参照。
