# ADR 0034: 実稼働区間を使う初期ヒントと非公開の実測入口

2026-10-12。状態: **技術候補を実装・比較中。製品の既定方式への採用、G0／MVP受入は未完了。** [ADR 0033](0033-checked-initial-incumbent.md)の独立検証・全候補探索・有効案保持を維持する。

`balanced-incumbent-v1`の貪欲ヒントは、部分的な休憩・予定を含む配置枠にも全枠分の供給を差し引き、資格者の同時サービスと役割比率を十分に参照していなかった。これはモデルやチェッカーの供給計算の誤りとは区別する。

新候補`balanced-incumbent-v2`は、モデルが既に持つ正確な状態変化区間を使い、選択勤務で実際に処理する区間だけ供給を更新する。需要は直接入力を優先し、0と未設定を区別する。資格者を先に処理し、区間ごとに単一役割を選ぶ。一般処理人数、役割を処理する人数、役割兼任者を除く分母を更新する。

役割の初期配分には、需要を業務の最大適格能力で割った仮の必要人数から比率を見積もる予約量も使う。この見積もりは実際の分母でも最終必要人数でもなく、ヒント専用の技術案。全必須条件と実際の役割不足・分母・丸め・段階目的は、従来のモデルと独立チェッカーで計算する。ヒントに合わせた必須条件の緩和、勤務候補の削除、手書き比較案の投入はしない。日内は単一業務を初期値とし、準備・継続・月／週条件の不適合時は限定探索を拒否して全候補探索へ進む。

実Cloudflare検証には、`POST /__poc/optimizer-benchmark`とContainerの`/benchmark`を追加する。Worker側は既存のPoC token・PoC環境・4MBの入力上限・正規入力契約・架空企業／チーム／スタッフ／ジョブIDを検査する。戦略は列挙値、予算は1〜120秒に限定する。入力は常に`synthetic-poc`へ送り、通常の会社・チームのジョブIDを選べない。Containerでも独立して設定と架空IDを検査する。

既存のcheck fenceと実行中フラグを使い、本体取得と実プロセス停止の確認後に応答する。512KBまでの要約を返し、配置のエクスポートやDB／R2への製品結果保存・公開は行わない。入力ハッシュ、全Pythonソースのハッシュ、全結果のハッシュ、評価・状態・資源・ランタイムを記録する。応答喪失は終了とみなさず、CLIは同じオブジェクトを観測して記録し、置換実行を自動で開始しない。

通常の`/solve`、製品の既定`legacy-first-v1`と20秒予算、公開判定、同一チーム1件のジョブ制御は維持する。非公開HTTP／RPCでの単発実測はQueues・D1／R2・画面表示を含む5分の受入とは別にする。測定ハーネスの子プロセス失敗／タイムアウトも記録して非ゼロ終了し、成功コマンドへ隠さない。

資源は既存の`standard-2`・最大1インスタンスを維持する。[現行公式仕様](https://developers.cloudflare.com/containers/platform/limits/)の1vCPU／6GiBは候補資源の仕様であり、実際の適合・品質・時間は計測で判断する。Workers型定義5.20261011.1を参照用に取得し、プロジェクトの依存版は変更していない。現在のWrangler4.149.0／Containers0.3.7で型・実HTTPを確認する。
