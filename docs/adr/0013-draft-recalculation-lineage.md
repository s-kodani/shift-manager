# ADR 0013: 手動編集画面と明示固定を参照する再計算

日付: 2026-10-11。状態: 限定実装・ローカル検証済み。対象: WP-05／06、Q81／82／92、勤務不可例外。確定製品仕様は変更しない。

## 判断

手動編集案は元ジョブ・入力の不変データとは別の版として保存する。画面の編集だけでは固定せず、勤務パターン・出退勤・休憩を個別に明示固定／解除する。担当業務の固定は追加しない。独立検証済みの結果を月間・日別・結果表示へ接続し、手動案に最適性の証明を表示しない。

再計算時は最新の製品入力を読み、選んだ最新編集版の明示固定だけを取り込む。旧入力・編集案の配置全体を複製して自動計算の正解にしない。理由付き例外は、本人・日付・区間が一致し、パターン／出退勤／休憩すべてが実配置どおり明示固定されたものだけを取り込む。固定なし・部分固定の例外は自動入力から除外する。理由・対象範囲を広げない。

`input_snapshot_draft`で凍結入力と編集ID・版を結合する。通常の入力凍結と古い通常入力によるジョブ受付も、保存済み編集headが存在すれば拒否する。D1トリガーは凍結・受付・結果採用時にheadを照合する。凍結後の編集／固定解除は入力revisionと独立して結果をSTALEにし、古い結果が新しい固定を無視して採用されることを防ぐ。単純に企業入力revisionだけを比較する案ではこの競合を検出できない。

派生計算からさらに手動編集すると、その派生入力の参照headは過去版になる。手動候補は現在の入力revisionを要求し、固定・例外を差し替えて配置全体を再検証し、保存時の期待headを原子的に照合する。この限定用途では元入力の編集headだけが古いことを理由に再検証を拒否しない。自動計算ではこの例外を使わない。

## 検証と限界

実施記録（過去の私有資料・公開対象外）を参照。実Workers／D1の競合試験、ローカル実Dockerによる認証・画面・独立チェック・再計算を区別して記録する。Cloudflare配備、公開・全条件・大規模性能・現場受入は未完了。R2とD1は分散トランザクションではなく、不確実な保存失敗で孤立オブジェクトが残る。GCは別課題とする。
