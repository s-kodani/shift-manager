# ADR 0083: 同じ候補分集合の配置幾何情報を共有する候補

2026-10-14。R-01。状態：技術候補・通常未採用。

前回の500人は配置構築108秒で未完了。架空101人・ローカルPythonのcProfile（CP入口中断）では、候補の圧縮分集合をPython setへ展開・unionする3,131回の処理が累積5.687秒、MinuteSet反復が約1,686万回だった。関数内計測27.434秒（全体27.798秒）をDocker受入の時間と混ぜない。

同じsolve内の候補分集合bitsの順序が一致するstaff-dayについて、分集合のunionをbitsのORで計算し、配置枠、各候補の正確な稼働分数、稼働候補index、開始済み候補indexを共有する。配置枠は元の分集合の幾何情報の枠keyから得る。契約・固定・休憩・取消・予定によって候補の稼働集合が変われば別keyとなる。indexの順序を維持し、solver変数は日ごとに生成する。共有値はtuple・読み取り専用mappingで保持する。

既存のshared_build_facts診断flag内だけを改善する。shared=Falseの通常経路は元の処理を維持する。共通継続量候補のprofile名は維持し、source SHAとimageで実装を識別する。CP proto・hintが同一になる変更として、両優先順位・30／60分・common=False／Trueで初回full protoを比較する。

候補削減・業務変数の共有・分単位の丸めは採らない。目的・ルール・役割計算・独立checker・予算を維持する。計画（過去の私有資料・公開対象外）／結果（過去の私有資料・公開対象外）で実装・等価性・実測・残課題を分ける。
