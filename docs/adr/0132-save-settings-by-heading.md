# ADR 0132: 設定を主要見出しごとに保存する

2026-10-17。ユーザー依頼「保存範囲が分かるよう、設定の見出し単位で保存ボタンを配置」を反映する。

## 決定

主要見出しを境界線で区切り、それぞれの末尾に「休憩ルールを保存」など対象名を含むボタンと、当該範囲だけを保存する案内を置く。個別行や入力項目の小見出しではなく、以下の設定群を単位とする。

| 画面 | 個別に保存する主要見出し |
| --- | --- |
| 企業共通設定 | 勤務時間・休日のルール／勤務可能曜日・時間帯／休憩ルール／習熟度の段階 |
| チーム設定 | チームの計算設定／業務／勤務パターン／担当区分／切替時の準備・移動 |
| スタッフ設定 | 勤務契約・個人ルール／業務ごとの習熟度／対応可能な担当 |
| 需要管理 | 必要人数／研修・会議／担当区分の必要人数 |
| 本人の申告 | 勤務不可日時／勤務の希望 |

企業カレンダー、雇用区分、勤務履歴、受付再開など、もともと1つの設定群で保存している箇所は独立した保存を維持する。参照専用の設定には保存ボタンを追加しない。

## 保存範囲と保護

既存APIのリソース・版競合・再送・独立検証は維持する。押した見出しの編集値を、直前に保存済みの同一リソースへ合成して送る。他の見出しの未保存値を混ぜない。保存済みのほかの値は保持し、ほかの見出しの不完全な入力は対象の保存を妨げない。Enterキーも入力中の見出しを対象とする。

保存の成功応答を受け取った見出しだけ未保存表示を解除し、ほかの入力と離脱確認を維持する。保存後の版更新・参照設定の再取得中にも、同一対象の編集フォームを保持する。保存失敗・応答不明では入力を保持し、既存の同一操作IDによる確認を使う。取得内容が自身の保存内容と異なる場合は古い全体データでの保存を止め、入力を残して最新内容の確認を求める。

## 初回登録と関連する変更

企業共通設定・チーム設定・スタッフ契約は、初回に必須項目を揃えて既存の完全なリソースとして登録する必要がある。初回はそのことを各見出しに案内し、末尾の「すべて登録」を使う。未設定値を勝手に補完しない。

業務の追加・削除と担当区分の対象業務や準備・移動など、複数群の整合が必要な変更は、部分保存で既知の不整合を通さない。「すべてのチーム設定を保存」など対象範囲を明記した一括保存も残し、必要な関連入力を揃えてから同時に保存できる。必須条件、認証認可、計算仕様、保存スキーマは変更しない。需要・本人申告は既存の有効な空配列を保存元として個別入力できる。

## 検証・影響

見出し別の送信範囲、未入力の他群の保持、連続保存、初回登録、関連変更の拒否と一括保存、版競合・応答不明、外部更新、PC／モバイルと既存リロード復元をブラウザーで確認する。既存APIの権限・入力検証・原子性もローカル統合試験で確認する。結果・反映範囲（過去の私有資料・公開対象外）へ記録する。最適化の変数・制約・目的・独立検証への変更はない。

2026-10-17の追加指定で、同じ見出しの追加ボタンと保存ボタンは共通の操作行に配置する。デスクトップでは追加の右隣に保存、700px以下では縦並びとする。対象は習熟度・業務・勤務パターン・担当区分・需要・研修会議・担当区分の条件・勤務不可・希望の9群。保存の契約は変更しない。

2026-10-17の追加指定で、需要管理の見出しを「必要人数の直接入力」から「必要人数」へ変更し、「担当区分の必要人数」と表現を揃える。見出しから生成する保存ボタン・保存範囲の案内、見出しのヘルプ、一括入力後の保存案内にも同じ名称を使う。直接入力の優先、算出値の保持、0と未設定の区別は維持する。

2026-10-17の保存失敗報告を受け、業務の能力係数の入力エラーは業務番号・習熟度名と理由を表示する。精度1で0.5などを扱えない場合は、使用する小数の桁数に合う能力係数の精度へ変更して全体保存する手順を案内する。全体保存でも同じ関連設定の定型文だけを繰り返さない。入力値・精度を自動補正せず、既存の正確な整数化と保存範囲を維持する。ローカル検証（過去の私有資料・公開対象外）。
