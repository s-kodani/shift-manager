# ADR 0099: calendar候補の全面的な既定採用を見送る

2026-10-14。技術判断。ユーザーはADR0098で性能改善を後続へ移し、案の品質と通常反映を継続する方針を決めた。

同じPython源・同じ架空101人30分入力で通常process方式とcalendar候補を比較した。3業務／2パターンでは通常評価[0,0,80,33822000]、calendar評価[630000,33786000,101,5634000]となった。両方独立checker VERIFIEDだが、calendarは先行する役割不足・一般不足・希望未充足が悪化している。余剰だけ減っても上位の悪化を打ち消せない。

calendar候補の明示設定による通常ジョブ接続（461360a）は維持するが、既定設定へ全面採用しない。実SDKで既定採用を検証する前提が崩れたため、その受入は開始しない。正常UNKNOWNの通常結果も、calendarによる別入力の成功で遡って合格にしない。

次の候補は、通常の初期案を先に試し、有効案を得られない場合だけ補助calendarを試す構成とする。通常で保持した独立検査済み案を悪い補助案へ置き換えず、辞書式評価と上位の保護を維持する。全候補・必須条件・段階目的・状態分類・内部120秒を維持し、補助探索は同じ予算の中で行う。実装・品質比較・実SDKの確認はこれからで、採用済みとはしない。
