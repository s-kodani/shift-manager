# ADR 0090: 初期案・構築・復元CPを順次別プロセスで実行する診断

2026-10-14。R-01。状態：診断統合・通常未採用。

初期案生成、全候補モデル構築、復元／CPを順番に別プロセスで実行し、前段の終了／回収を確認して次へ進む。構築用データをCP開始前にOSへ返す目的で、同時起動や資源増量はしない。

親は初期案を全条件・入力hash／lineageで再検査し、そのファイルSHAを構築側へ渡す。構築側はファイル一致を確認して保存案として元モデルへ渡し、モデル側の保存案検査を維持する。受渡しmanifestのtrusted SHAで全モデル・目的・抽出mapを復元する。

まず固定hintのCP実行可能性を検査し、独立checkerとの目的一致を確認して保持する。制限seedのOPTIMALは全体最適証明にせず、元の全体段階目的へ進む。親は結果を再検査し、より良い整数vectorだけ採用する。初期案CHECKED／UNKNOWNと全体CPのFEASIBLE／OPTIMALを区別する。

profile `mvp-split-process-v1`のみ全体240秒・初期最大72秒・構築最大120秒・復元／CP最大90秒を残時間に収める。通常120秒・Worker許可profile・保存／公開は維持。240秒は5分目標へ収める検証候補で、費用最適や性能達成ではない。

期限停止では完全な検査済みcheckpointだけ保持し、自然な非0終了は拒否する。子group停止・wait・一時領域回収を行う。全体CPのINFEASIBLEと検査済み案が矛盾すれば失敗にする。

計画（過去の私有資料・公開対象外）／結果（過去の私有資料・公開対象外）。大規模サイズ・text parseのpeak・全体時間・最終品質は実測で確認する。Cloudflare追加0、最終一括、定期backup保留／30日、試験導入範囲外。
