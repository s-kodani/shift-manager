# ADR 0140: 需要管理のタブ・CSVモーダルと変更比較の分類

2026-10-24のユーザー指定。既存の作業中変更を維持して表示と導線を変更する。保存・公開の条件、DB、最適化モデルは変更しない。

需要管理を「必要人数」「研修・会議」「担当区分の必要人数」のタブに分ける。初期表示は必要人数。一括入力は初期折り畳みとする。非表示のタブと折り畳み内の入力をマウントしたまま保持し、入力値・確認結果・表の絞り込みとページ位置を失わない。見出し別保存と全体保存を維持し、不正な入力があれば該当タブ・折り畳みを開く。表のページ外で見つかった入力エラーも対象行を表示する。

対象月の右側に「需要CSVの取り込み」を置き、取り込みをRadix Dialogへ移す。狭い画面では月の後へ折り返す。閉じても確認結果を保持し、全件中止または反映成功時に破棄する。確認・反映中は閉じる操作を拒否する。未保存値がある場合の選択・反映制限、正常行のみ反映、版競合検査を維持する。エラーと応答不明時の「同じ操作を確認」はモーダル内に表示し、既存operationIdで回収する。閉じたら起動ボタンへフォーカスを戻す。

変更比較のタイトルを「計算時からの変更」とし、「入力条件の変更」「公開版・公開勤務の変化」を分ける。後者は差分pathの先頭が`published`／`mode`、または`sources/published_schedule`の項目。勤務履歴、公開勤務に由来する履歴、固定・固定解除・例外は計算に使う入力条件として前者へ残す。これは表示分類であり、古い案の判定・独立検証・公開条件を緩めない。

既存差分APIのURL・クエリー・50件ページ分割を維持し、応答に`totals: { input, publication }`を追加する。全差分からカテゴリ別総件数を計算し、各枠に総件数と取得済み件数を表示する。追加取得は共通とし、未取得のカテゴリを「変更なし」と表示しない。版競合時は比較全体を破棄する。

お知らせの再取得は、カード見出し右上の更新アイコンへ変更する。元の文言を読み上げ名・ツールチップに使い、更新中は回転表示と操作無効化を行う。

検証記録と再実行手順（過去の私有資料・公開対象外）。ローカル検証後の反映依頼により、2026-10-24 20:05 JSTにCloudflare版`26a2a70a`へ配備し、実配信資産・PC／モバイル表示・停止状態を確認した。実業務書込・計算・Container更新は行っていない。
