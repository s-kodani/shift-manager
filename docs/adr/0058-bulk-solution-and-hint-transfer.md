# ADR 0058: 完全なCP解の値と探索ヒントを同じ順序で一括転送する

日付: 2026-10-13。対象WP-03／TS-OPT・PERF。基点`8bc7c25af120f1b7b16b3205d0e19ccd24d5db80`。日別上限候補（過去の私有資料・公開対象外）は通常採用しない。今回は制約・上限・候補・探索方式を変えず、Python側の値読み出しと完全ヒントの構築を対象にする。

## 根拠と変更

前回500人の初期工程は約32〜35秒で、CP呼出し約10〜13秒と独立検査約12秒以外にも時間がかかった。現行コードは約96万個の変数について、`get_int_var_from_proto_index`／`value`と、もう一度`get_int_var_from_proto_index`／`add_hint`を個別に呼ぶ。まずextract・値読み出し・ヒント構築の実測を分け、実際の負担を確認する。

固定版OR-Tools 9.15の実装を確認した。`value`はCP responseを使って式を評価し、`response_proto.solution`は元の正の変数index順の整数解ベクトルを持つ。[公式proto](https://github.com/google/or-tools/blob/v9.15/ortools/sat/cp_model.proto)も元モデルの全変数との一対一対応と、ヒントindexの一意性を定義する。`add_hint`は正indexと整数値を`solution_hint.vars`／`values`へ追加する。候補はこの2つの完全ベクトルを一括で読み書きする。

- 成功したCP解の全変数値だけが対象。線形式や否定リテラルの値は従来のAPIで取得する。変数を間引かず、auxiliary変数・定数も含める。
- CP responseの解の長さが現在の変数数と一致しなければ拒否する。別モデル／未取得の解を採用しない。
- 元のヒントを消し、index`0..N-1`と同じ値を同じ順序で設定する。元の完全ヒントとproto上でも一致させる。
- solve後の保護上限制約で定数が追加された場合は元の処理と同じdomain値を補う。未解決の非定数は`UNSOLVED_NEW_VARIABLE`で拒否する。
- 独立チェッカー・目的一致・初期案採用・保存案の比較・上位評価保護・段階証明・状態分類は変更しない。完全ヒントは助言であり、通常の本探索で固定へ変換しない。

## 比較と採用判断

最初の比較imageでは通常False／候補Trueを各1回測定した。同じ全解・全hintと正解比較の一致、一括転送工程10.840秒→0.315秒を根拠に、HTTP通常profile`mvp-joint-v1`と保存案診断profileでTrueを採用する。Python／CLIの引数既定は互換性のためFalseを維持する。120秒・1 CPU／6 GiB・seed0／worker1・前処理あり・全候補・段階目的・別HTTP検査を維持する。Workersの通常要求・結果採用条件は変更しない。

`npm run test:compute-solution-transfer-native -- <manifest.json> <image-id>`は終了済みfixtureから保持した全500人の元固定入力に限定し、同一SHA・同じimageで各1回を測る。未発見・失敗の自動再試行は行わず、実kernel資源・所有コンテナ終了まで記録する。採用後の比較commandは固定の従来profile`mvp-joint-loop-solution-transfer-v1`（False）と一括profile（True）を比較する。最初のimageでの「通常False」と最終imageでの「通常True」を混同しない。実施記録（過去の私有資料・公開対象外）へ両版と最終通常経路の確認を残す。

両方式の全体時間は112.324／113.641秒で短縮を確認していない。モデル準備60.496／46.702秒、本探索要求3.248／33.979秒と実行条件の変動があり、kernel最大3.54／5.32 GiBの差を一括転送単体の因果効果とは判定しない。希望未充足500件・目的一致のままで、性能／品質改善達成とはしない。6 GiBの資源上限・120秒設定を増やさず、通常経路の最終検証と回帰を完了してからcommitする。

## 検証する同等性

負の整数・Bool・定数の実CP解、解の長さ不一致・後から追加した定数／非定数・空モデルを確認する。30／60分、準備・7分研修・会議・固定休憩・取消・予定のみ・固定例外の各CP呼出しで、全制約・目的・完全ヒント・解が一致することを確認し、独立全列挙の最適値へ照合する。保存案からの競合初期案と全目的段階、時間切れ時の検証済み初期案保持も対象にする。

一括転送と、計算全体の時間・希望／余剰品質・反復安定性・資源余裕・実SDK／全UI／Cloudflare互換性は別に判定する。時間超過を隠す計測補正、独立検査省略、条件緩和、固定追加や無条件の資源拡大は行わない。
