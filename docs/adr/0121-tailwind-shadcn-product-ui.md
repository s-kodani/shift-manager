# ADR 0121: Tailwind CSSとshadcn/uiによる製品画面の統一

日付: 2026-10-16。ユーザー依頼に基づく追加改修。実装・ローカル確認とCloudflare反映を区別する。実施結果（過去の私有資料・公開対象外）を参照。

## 判断

2026-10-15〜16のユーザー決定により、候補だったTailwind CSS＋shadcn/uiを採用する。対象は管理者・スタッフ・ログイン・パスワード再設定の製品画面全体。白・グレー基調のライトテーマへ刷新し、既存の画面構成・業務操作・日本語表記を引き継ぐ。参照保存版モックは変更しない。

既存ViteにTailwind CSS 4.3.3／`@tailwindcss/vite` 4.3.3を追加する。shadcn/uiの部品をローカルソースとして管理し、`components.json`にnew-york／neutralとaliasを記録する。ButtonのvariantはCVA、クラス結合はclsx／tailwind-merge、対話部品はRadix UIのAlert Dialog／Toast／Tabsを用いる。標準入力・選択・チェックは、FormData・required・ラベル操作・変更イベント捕捉を維持するネイティブ要素へ適応する。フォーム管理・ルーター・DB・最適化条件は追加変更しない。

- カード内側はPC24px／モバイル16px。ラベルと入力欄8px、フォーム項目24px、操作ボタン12pxを基準にする。
- ユーザーの追加指摘に従い、セレクトの下矢印は右端から12px、文字の右余白は40px。高コントラスト環境では標準矢印を使用する。複数選択・複数行選択の標準動作は保持する。
- 2026-10-16追加指摘: シフト画面の表示タブと状態案内の間に24pxを設ける。企業共通ルールの段階追加・保存ボタンは12px間隔とし、段階削除は各段階の左端のマイナスアイコン（段階番号付き読み上げラベル）にする。モバイルで入力欄と重ならない配置を維持する。
- CSVテンプレート取得ボタン直後の区切り線を含め、detailsの上側に24pxの余白を設ける。
- 操作結果は右下トーストへ集約。成功・案内は5秒、警告・エラーは手動終了。入力エラー、検証結果、応答不明時の確認操作、お知らせ履歴は画面にも保持する。
- 初回取得と対象切替にはスケルトン、認証確認とボタン操作にはスピナーを使用する。取得失敗を空データへ読み替えず、応答不明を通常のロード表示に放置しない。同じ対象の再取得と追加取得は既存情報を保持して状況を表示する。
- 未保存入力の確認は非同期Alert Dialogへ移行する。入力変更時の選択値を待機前に保持し、フォーム送信は確認後の新しいイベント処理でrequestSubmitする。再送元ボタンと入力所有者を保持する。ブラウザー離脱のbeforeunloadは維持する。

## 公開再設定画面

`/reset`のHTMLとスクリプトは継続する。共有テーマを別Viteビルドで`dist/app/assets/reset.css`へ生成し、既存の公開URL `/reset.css`からASSETS経由で返す。従来のCSP・no-store・トークンのメモリ保持／fragment除去を維持し、公開パスを増やさない。CSSも既存の静的資産manifest／最終復旧検証の対象になる。

## 代替案と検証の境界

独自CSSへの局所修正の継続は、共通部品と余白の統一という今回の依頼を満たさない。アプリ全体を新しいフレームワークやフォームライブラリへ移行する必要もない。既存のReact／Viteと認証・権限・状態遷移を保持して移行する。

Tailwind CLIは一度依存候補を取得したが、監査で開発用watcher経由のHighが確認されたため採用せず、ViteによるCSSビルドへ統一した。最終のnpm監査は実施結果へ記録する。

2026-10-15の配備済みMVP受入は当時の凍結版の証跡として保持する。今回追加したUIのローカル確認を、その配備版や実端末・大規模性能の追加合格に読み替えない。
