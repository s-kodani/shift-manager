# ADR 0107: 最終PoCで通常の製品経路と実行コンテキストを使う

- 日付: 2026-10-15
- 状態: 採用・ローカル検証済み／Cloudflare未配備
- 対象: R-07、TS-AUTH／API／UI、最終一括確認の準備

従来の非公開PoCは専用probeと一部の認証だけを外部へ中継し、通常の業務API・製品画面へ到達できなかった。最終確認で実際の製品APIとビルドを通すため、PoCトークンを照合した後、登録済みmethod／pathの業務APIと `/app`／明示的なapp資産を製品ルーターへ渡す。ENVIRONMENT=pocに限定し、トークンなし・異なる環境は拒否する。未知ルートは従来の404を維持し、閉鎖したauth signup／admin経路を開かない。

トークンはPoCの外側の非公開化であり、Better Authのsession・初回変更・利用停止・企業／チーム権限を代替しない。実WorkerのExecutionContextも渡し、計算受付後の `waitUntil` による配送を保持する。最終検証用の別実装へ業務処理を複製しない。通常の製品Workerのルーター・製品仕様・モデルは変更しない。

最終PoCのAI設定はユーザー指定の今回範囲外に合わせdisabledへ変更する。既存のAIコード／bindingは保持し、実AI・通常メール・定期backupを実行しない。

ローカルの実Better Auth／workerd D1/R2と制御Queueで、外側token・初回変更403→変更後200・会社外403・利用停止と、202後の同じ実行コンテキストから配送1件を検査する。実Queues／Containers・ブラウザー・Cloudflareの結果とは分ける。初回の存在しないteams GET期待値、Queue metadata型、未知ルートの404回帰を修正前／後で記録する。

実施記録（過去の私有資料・公開対象外）／最終計画（過去の私有資料・公開対象外）。独立レビュー・凍結・実環境一括確認が通るまでMVP完成や遠隔互換性を宣言しない。
