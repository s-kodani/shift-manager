# ADR 0014: 入力登録での固定・理由付き例外の参照

日付: 2026-10-11。状態: 限定実装・ローカル検証済み。対象: WP-02／06、Q81／82／92／110。確定製品仕様の変更なし。

## 判断

月別の研修／会議・勤務不可入力を保存する際、サーバーが最新の編集headと不変R2オブジェクトを読み、digest・企業／チーム／月・現在の権限を照合する。保存済みの明示固定と全面固定の理由付き例外を、予定参加者の登録事前検査へ取り込む。クライアントが承認済み例外や参照headを指定することはできない。

例外抽出は再計算と同じ`fixedDraftInput`を使い、本人・日付・区間・実配置が一致する勤務パターン／出退勤／休憩の全面固定だけを許可する。部分固定や固定なしの手動理由は保持できるが、自動配置の許可として使わない。入力変更で古くなった編集版も、現在headであれば固定の根拠として読み、新しい入力条件とは改めて照合する。

予定の全時間参加が可能かを確認する際、既存のパターン固定・時刻固定・休憩固定も照合する。固定された自動休憩を別時刻へ移動して登録を通さない。予定参加者以外の未完了の契約設定は、従来どおり登録の妨げにしない。

`input_registration_draft`に、検査に使った編集ID・版を入力操作と同じD1 batchで記録する。headがない場合も「版0・IDなし」を記録し、検査中の初回固定を検出する。headが途中で変わればトリガーでABORTし、入力操作・入力版・企業revision・監査をロールバックする。入力revisionだけの比較では、固定解除を検出できない。

## 検証・代替・限界

[D1 batch公式仕様](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)を確認し、ローカルworkerd／D1で途中競合のロールバックを実測した。R2とD1全体が原子的になるという主張はしない。R2は不変データの照合を担当し、D1の最終参照照合が採用を制御する。

DBだけの登録検査は理由付き固定例外を参照できず、予定と勤務不可が重なる入力を一律に拒否していた。クライアントから例外を添付する代替は、許可根拠を捏造できるため採用しない。現在headを読んだ後にD1でも照合する構成を選んだ。

実施記録（過去の私有資料・公開対象外）を参照。登録事前検査は予定参加可能性と対象入力の検査であり、完全な月次配置の独立検証・実行可能性証明・公開判定ではない。Cloudflare配備・実環境障害・全受入は残る。
