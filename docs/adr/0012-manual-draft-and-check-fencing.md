# ADR 0012: 手動編集版を独立検証して保存する

日付: 2026-10-11。状態: ローカル実装・試験済み。今回のCloudflare配備は未実施。対象: WP-06、Q81／82／92、勤務不可例外。製品仕様は変更しない。

## 判断と理由

入力スナップショット・計算結果を上書きせず、手動編集は独立の版系列へ保存する。D1の`company.revision`を入力版、`schedule_draft_head.revision`を企業・チーム・月ごとの編集版として扱う。編集は必須条件を変えないため、編集だけで入力版を進める案は採らない。保存には両方の期待版と元の成功ジョブを指定し、古い入力・編集版の上書きを拒否する。手動案には計算元のsolverStatus・目的関数の最適性証明を転記しない。

サーバーで凍結入力を読み直し、明示固定と例外だけを置き換えた候補を、同じチームのContainer RPCから`/check`へ渡す。クライアントの検証結果・入力条件を信用して保存する案は採らない。Pythonと生成Zodの出力形を共通JSON Schemaへ集約し、分単位の役割区間を維持する。独立チェッカーの既知違反は下書きでも保存を拒否する。履歴不足の参考案は別状態として保持し、公開は引き続きBLOCKED_A1。

理由付き手動配置には`lockId: null`を許可し、編集しただけで固定したことにしない。独立チェッカーでは、本人・日付・理由・実際に残る拘束区間に含まれる例外だけを勤務不可検査へ適用する。月最低勤務量等の他の必須条件は維持する。自動ソルバーの入力検証は、この固定なし例外を拒否する。将来の再計算では明示的な完全固定に対応する例外だけを取り込む必要があるが、その編集版からの取り込みは今回未実装。担当業務固定は追加しない。

## 原子性と停止確認

R2にはサイズ制限・SHA-256付きの不変オブジェクトを先に保存する。D1のmigration0010は、保存時点の権限・初回変更・enabled、入力版・元ジョブ・スナップショットの同一性と編集版をINSERTトリガーで検査する。版台帳・最新head・監査は同じbatchで更新し、監査失敗もロールバックする。同じ操作の再送は履歴を返し、後続版を戻さない。R2とD1は単一トランザクションではないため、D1拒否後の孤立オブジェクトは残す。安全なGCは別途必要。[D1 batch](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)の原子性をworkerdで検査する。

Containerは既存の計算とチェックで同じ実行排他を使う。チェック前にSQLiteの`check_fence`を永続化し、停止確認成功後にだけ消す。停止が不明なら結果を返さず、フェンスを保持する。DO再生成後の次のチェック・計算は、残ったチェックプロセスの停止を確認してから進める。計算フェンスが残る場合にチェックで計算を追い出すことはしない。診断・idle解放も両方のフェンスを尊重する。[ContainerとDO永続ストレージの公式仕様](https://developers.cloudflare.com/containers/api/container-class/)に従う。

## 結果と制約

実施記録（過去の私有資料・公開対象外）に、実ContainerのAPI保存・違反拒否・停止、制御したプロセスを使うDO試験を区別して残す。新しいライブラリ・ソルバーは採用していない。編集画面、固定解除の画面、編集版を使う再計算、公開・履歴取得の全導線、Cloudflareでの今回のチェックRPC・異常停止再試行、全受入・性能は未検証。今回の実装はWP-06の基盤であり、WP-06／MVP全体の完了ではない。
