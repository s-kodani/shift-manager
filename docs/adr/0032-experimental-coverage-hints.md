# ADR 0032: 需要と休憩分散を参照する探索ヒントの比較

日付: 2026-10-12。状態: **技術候補を実装し、ローカル比較中。製品の既定方式への採用は保留。** 製品要件、勤務候補、制約、目的の段階順序、独立チェッカーは変更しない。

従来の `legacy-first-v1` は、各日の最初の勤務候補と最初の適格業務を初期値として渡す。基本ケースで有効案は得られたが、長い勤務候補や需要配分を利用しないため、不足が残る。

比較候補 `balanced-coverage-v1` は長い勤務候補を選び、同じ勤務量の休憩候補をスタッフ間で分散する。日別の残需要と資格者の役割最低人数を参照し、1日の担当業務・処理中の役割を部分ヒントにする。これは貪欲な近似で、役割比率、複数役割の重複条件、部分枠の能力、月・週上限、希望を正確に最適化する初期案ではない。固定・勤務不可等による候補の除外は従来のモデル構築が行い、ヒントによる候補削減や強制固定を追加しない。

CP-SATが初期値を修正して全制約を解いた結果だけを独立検証する。小規模の全列挙比較を両方式で行い、長い勤務ヒントが月上限を超える場合・短い勤務ヒントが月下限に足りない場合も検証する。ヒント生成にも構築期限を適用し、期限超過を `UNKNOWN / NOT_RUN` として返す。

`--hint-strategy` は比較用CLIだけの選択で、製品入力契約には追加しない。製品HTTPとCLIの既定値は従来方式を維持する。基本ケースの改善だけで高負荷全体へ採用せず、役割・研修・固定を含むケースと実Containerでの品質・資源を確認する。

各実測は新しいPythonプロセスで逐次実行する。最大RSSを複数計算の累積値にせず、入力・ソース・結果のハッシュ、探索段階の証明状態を保存する。比較案はモデルの候補生成を使わず手書きする。独立チェッカーが認める比較案の目的ベクトルは達成可能値であり、最適値の証明ではない。実施結果（過去の私有資料・公開対象外）を参照する。

CP-SATのヒントと状態分類の参照元: [OR-Tools公式のsolution hints](https://github.com/google/or-tools/blob/stable/ortools/sat/docs/model.md#solution-hint)、[公式CP-SATソルバー文書](https://developers.google.com/optimization/cp/cp_solver)。依存は実ロックの9.15.6755を使用し、上流stable文書だけでこの版の互換性を確認したとは扱わない。
