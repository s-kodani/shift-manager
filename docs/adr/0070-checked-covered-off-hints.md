# ADR 0070: 完成した初期値の充足を維持して希望休日を選ぶ

2026-10-13。WP-03／04・R-01。基点b90b6ae96576f1a7c19e30736af3e1281b5dc5f8。事前計画（過去の私有資料・公開対象外）／結果（過去の私有資料・公開対象外）。製品の勤務条件・重み・目的順序・固定・公開後維持は変更しない。

## 採用する方式

従来v4の一日分の初期値をまず完成させ、希望休日の対象者を除いた分単位の供給・実役割分母／人数を計算する。全一般・役割不足を0に維持し、休日候補が存在し、その日の希望が休日1件だけで、全ルールの月最低時間・日数を残せる場合だけ休日の初期値へ変更する。複数人／複数日の変更では残量と供給・役割を更新する。直接0を未設定と扱わず、役割最低人数と比率の最大値・企業丸めを参照する。

休日でも内部の論理業務選択はone-hotで保持する。実稼働が0なら出力の業務・供給・役割を持たず、未割当待機を許可する変更ではない。空の勤務候補領域や固定・研修を変更せず、CP-SATに元の全モデルの不可能証明を委ねる。

初期値は解答や制約ではない。同じ全モデルの制限付きCP実行可能性と独立検証・評価一致を通した案だけを本探索へ保持する。候補が不採用なら同じ初期配分の残り時間で従来seedを試し、初回候補の状態は別metricsに残す。通常本探索の勤務／業務候補を減らさない。

## 不採用案と根拠

早い段階の充足だけで休日を選ぶ初期案は、後続の一般スタッフが役割分母を増やす反例で、従来0の役割先行不足を60,000へ悪化させた。3業務で内部選択を全0にする実装も制限探索INFEASIBLEとなり、4条件とも従来案へfallbackした。この初期案は採用しない。完成した初期値からの除去に改め、反例・3業務・空領域を回帰へ追加した。

両役割表現、30／60分・両優先順序の独立全列挙／初回全proto照合、全Python479件を確認した。同源・同入力・1 CPU／6 GiB・120秒の4条件で先行不足・余剰を維持して希望101→80／500→379、保持した500人固定入力でも500→379を確認した。通常実SDK101人の登録・初回変更・Queues／DO／solve・別check・停止先行・D1／R2保存・読取・終了も確認した。

## 選択と限定

通常設定に新profile `mvp-joint-covered-off-hints-v1`を選ぶ。Workerはprofile・120秒・v4・coveredOffHintsEnabled=trueを保存前に照合する。従来`mvp-joint-v1`と保存案profileを互換・診断用に維持し、Python引数の既定Falseも維持する。未配備の設定更新と、配備済みCloudflareの動作確認を分ける。

単発の各1組から反復保証・全体最適性・希望完全充足・5分の全操作目標を主張しない。固定入力での約0.64 GiBのメモリ余裕、CP内部時間超過、通常実SDK案の一般不足30,000、初回Proxy接続断、全SDK／UI／復旧・G0〜G2・試験運用は残す。Cloudflare追加0、最終一括・定期backup保留・30日保管を維持する。
