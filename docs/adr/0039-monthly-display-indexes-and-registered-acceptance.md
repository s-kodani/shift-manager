# ADR 0039: 月間表示の索引化と登録済み入力の大規模検証

2026-10-12。状態: 月間表示へ採用・限定受入。確定製品仕様・勤務条件・目的段階・独立チェック・150秒通信期限は変更しない。画面の実施記録（過去の私有資料・公開対象外）／登録・計算の実施記録（過去の私有資料・公開対象外）。G0〜G2とMVP全受入は未完了。

## 月間表示

従来はスタッフ・日付のセルごとに全配置を`find`で検索し、各セルの名前もスタッフ一覧から検索した。500人・31日なら15,500セルで約1.2億回の配置行比較になる。受信した配置配列からスタッフ→日付のMapを一度作り、スタッフ名もIDのMapを作る。配列が更新されたときに索引を再作成し、対象月の変更で日付一覧を更新する。

同じID・日付が重複した異常データでは従来と同じ最初の行を使う。業務の保存・公開前の重複検査は別で維持する。勤務時刻、休日、未確認、案なし、ARIA、日別へのcallback、現在のマスタにいないスタッフの表示を変更しない。識別子と日付の単純な連結によるキー衝突を避けるため、二段のMapを使う。

ページング・仮想化による行の省略は今回採用せず、500行の表示と末尾の操作を検査する。追加の索引メモリは配置行数に比例する。小規模の検索継続や全セルでの再走査に比べ、結果が変わらない再表示の検索を抑えられる。

## 検証の区別

月間コンポーネントと製品CSSのブラウザー比較、workerd上の表示選択試験、登録・コンパイル・実Docker計算の業務関数試験を分ける。実ブラウザー比較は匿名化した架空ソルバー結果で、認証・製品API・Queues・画面の一連の計算時間の受入ではない。

登録済み検証は500人を100行以下のCSVに分け、企業／雇用区分／個人ルール、月別入力、需要／役割／研修、確認済み履歴を通常の業務関数へ登録する。通常コンパイラーから実ソルバーへ渡し、初回案取得後に独立チェック済みの手動固定例外を保存して再計算する。手書き比較案をソルバーの返答・探索ヒントへ流用しない。履歴の必要範囲の選択と元履歴保持を別々に検査する。

初回認証は既存の別受入に分離し、試験管理者の初回変更フラグだけをfixture内で解除する。新スタッフの初期パスワードは一時的にのみ保持し、出力・保存しない。終了時に試験企業の資格情報を終了し、所有Dockerだけを停止する。実Queues、DOの本物の終了RPC、認証ブラウザー、実Cloudflare全導線の代替にはしない。

定期バックアップ有効化はユーザー指示の保留、保管30日、Resend実配送disabledを維持する。
