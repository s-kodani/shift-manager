# ADR 0123: 計算準備の読取チェックと通知5秒

2026-10-20変更：[ADR 0135](0135-schedule-workspace-details.md)により準備チェックを独立画面へ移し、全項目を展開する。古い案の差分は見出し右横のinfoから参照する。以下の従来配置・折りたたみの記述は当時の記録として扱う。

日付: 2026-10-16。ユーザー承認済みの実装計画に基づく。

## 決定

2026-10-18補足：[ADR 0133](0133-published-pattern-conflict-guidance.md)で、公開済み勤務と現在の勤務パターンの不一致を研修・会議の出席不可と分け、チーム設定の復元を案内する。入力を組み立てられた場合は整合性エラーがあっても勤務履歴の登録状況を照合する。

2026-10-16補足：[ADR 0127](0127-demand-coverage-readiness.md)で、企業共通の勤務可能曜日・時間帯に対応する需要登録範囲を照合する。未登録枠は保存済みでも完了にせず警告し、日付・時間帯・業務を案内する。警告だけでは計算を停止しない。

管理者の「シフト・計算結果」の対象選択直下、公開済み勤務より前に「シフト計算の準備」を表示する。企業カレンダー、共通ルール・休憩、チーム、計算対象者、個人契約・参照先雇用区分、対象月の需要・予定、既知の整合性を確認する。完了項目は折りたたみ、不足・要修正・未確認は理由と修正先を示す。企業設定権限のない担当管理者には企業管理者への依頼を案内する。

必須の不足・矛盾、取得中、取得失敗、対象・入力版・編集版の不一致では新規計算を無効にする。履歴不足は参考案計算を許可し、公開前の確認・再計算を案内する。勤務希望の未提出、予定・役割条件の未登録、保存済みの空の需要は新たな禁止条件にしない。需要0件には案内を示す。準備完了は有効解の存在や公開可能性を保証しない。応答未確認時の同一受付確認と、計算受付・保存・公開時の検証を維持する。

`GET /api/companies/:company/inputs/teams/:team/readiness/:month`は管理権限を確認し、対象、入力版、編集版、9項目、計算開始可否を返す。ブラウザーでも応答形式と対象・版を検査する。共有の入力収集・組立と既知の条件検証を利用し、下書き固定・許可済み例外・公開勤務とスタッフ状態の扱いを通常計算に合わせる。旧公開版はR2証明と解除履歴を読み、メモリ上で固定を復元する。DB/R2への保存、補助情報の補完、ジョブ・ソルバー・独立チェッカーの起動は行わない。取得前後で権限と入力・編集版を確認し、通信・ストレージ障害を設定不足に読み替えない。DB migrationは不要。

画面表示、対象切替、設定保存後の再表示、入力・編集版変更、ウィンドウ復帰、明示再確認で取得する。対象が変わった旧応答を破棄する。修正画面への遷移も既存の未保存入力確認を通す。

成功・案内・警告・エラーのトーストをすべて5秒で自動終了する。Radixのホバー・フォーカス中の停止、閉じる・スワイプ・読み上げを維持する。画面内のエラー・違反・未確認説明と再確認操作は通知終了後も保持する。

## 代替案と検証

画面で設定の存在だけを見る方式は、個人契約の矛盾や公開・編集固定、権限・版を確認できないため採用しない。チェック時に計算を起動する方式も採用しない。最適化による解の存在証明は従来の計算・独立検証に委ねる。

ローカル検証（過去の私有資料・公開対象外）とCloudflareの限定反映（過去の私有資料・公開対象外）で、実行済みの範囲を記録する。Container更新と追加の遠隔シフト計算は行わない。
