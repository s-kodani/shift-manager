# ADR 0097: 運用・メール・AIを今回のMVP完成条件から除外

- 日付: 2026-10-14
- 状態: ユーザー決定
- 根拠: 残対応7項目の説明への回答「運用・メール・AIはMVPスコープ外でよいです」
- 先行決定: [ADR 0072](0072-mvp-development-delivery-scope.md)

## 今回の範囲

残タスクR-05「運用・メール・AI」を後続工程へ移す。本番運営者の認証方式・秘密情報の引渡し、監視・障害対応体制／手順の整備、認証済みResend送信元の決定と通常メール送信の有効化、AI説明の代表評価・実生成・費用枠は今回の完成条件に含めない。送信元ドメイン・運営体制・AI評価条件の回答を開発の前提として待たない。

残対応はR-01計算、R-02技術的な障害復旧、R-03公開後操作、R-04入力・画面、R-06対象要件の品質判定、R-07最終Cloudflare確認の6項目。R-08試験導入・現場評価の範囲外は維持する。G0／G1は今回対象の技術要件だけで判定し、対象外を試験合格へ読み替えない。

R-02では二重実行・古い結果採用・重複通知の防止、処理中／配送中の整合、復元後の認証・権限と業務再開の安全性を維持する。バックアップ定期運用、全サービスのRPO24時間／RTO1時間の運用達成判定・運用手順の完成は後続工程へ移す。復旧試験の時間は実測として記録できるが、運用目標達成を今回の完成条件にしない。

メール除外はメールアドレス／パスワード認証の除外ではない。Better Auth、初回パスワード変更必須、企業・チーム・本人境界を維持する。アプリ内シフト通知・計算の状態／不足／違反の表示・独立検証も今回対象。AIが条件・公開・承認を自動変更しない製品仕様を維持する。

## 実装と既存記録

実装済みの運用・メール・AI機能や試験・証跡は削除しない。製品仕様の正本と最適化制約・目的関数は変更しない。今回は納品範囲と判定対象の変更であり、旧記録のR-05未完了は当時の記録として残す。TS-AI、TS-NEW-15の通常メール／運営体制部分、TS-RECの運用目標部分を後続工程へ分類する。対象外機能でも認証・権限・秘密管理の既存回帰は維持する。

Cloudflareはローカル優先・最終一括。追加配備・計算・メール・AI実行はこの範囲変更では行わない。通常メールdisabled、定期バックアップ有効化HOLD、バックアップ30日保管を維持する。実装計画・テスト戦略・残タスク・品質対応表・最終Cloudflare計画を同期する。
