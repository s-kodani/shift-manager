# ADR 0084: 子プロセス障害前の工程を親で保持する

2026-10-14。R-01／R-02。状態：実装済み・採用前の規模診断。製品の判定仕様は変更しない。

前回の500人OOMで、HTTP 500だけが残り失敗工程と子回収結果を取得できなかった。子の工程境界、構築中5秒以上間隔の進捗、主モデルのseed／段階CPの開始・終了を、親が所有する一時ディレクトリへ原子的に保存する。補助calendar CPはinitialHints工程の範囲として観測し、各補助CPを個別計測したとは扱わない。

記録は最大64件・64 KiBで、固定enum・経過秒・変数／制約数・子RSS／最大RSS・モデル構築完了Bool・CP状態だけ。入力、識別子、モデル、assignment、資格情報は含めない。RSSはLinuxの実RSS、他環境で取得できなければnull、最大RSSはOSの単位を換算して記録する。

正常・期限停止ではmetricsへ観測を追加。非0／signal終了は実行失敗のまま、checkpointがあっても採用しない。親のwait後にファイルをサイズ・キー・型・enumで検査し、不正／欠落は取得不可とする。専用一時ディレクトリはfinallyで削除する。

内部診断profileのHTTP 500に検査済み観測と子exit／回収を含める。通常profileのHTTPエラーは従来MODEL_ERRORを維持する。診断runnerはこの小さな失敗情報を保存し、失敗を合格にしない。候補・制約・目的・hint・CP設定・独立checkerは維持する。callbackの保存障害は計測失敗として数え、最適化の制約違反へ読み替えない。

HTTPアクセスログや子stderrを全面保存する案は、入力／識別子の露出や容量増加を避けるため採らない。再計算で再現を繰り返す前に、1回の失敗から診断する。

計画（過去の私有資料・公開対象外）／結果（過去の私有資料・公開対象外）。Cloudflare追加0、最終一括、定期backup保留／30日、試験導入範囲外。
