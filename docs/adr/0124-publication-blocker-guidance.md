# ADR 0124: 公開不可理由と対応先の具体化

2026-10-20変更：[ADR 0135](0135-schedule-workspace-details.md)により準備チェックを独立画面へ移し、全項目を展開する。古い案の差分は見出し右横のinfoから参照する。以下の従来配置・折りたたみの記述は当時の記録として扱う。

日付: 2026-10-16。ユーザーの追加依頼に基づく。

## 決定

公開前に一律の「履歴不足・必須条件違反・古い案」を表示する方式を廃止する。その案の検証結果・入力版・編集版に基づき、該当する理由だけを表示し、複数ある場合はすべて示す。

- 履歴不足: 計算時点の未確認履歴をスタッフ名・番号と日付で示す。スタッフごとの修正ボタンで同じ企業・チーム・対象月の勤務履歴へ移動し、該当者を選択、最初の不足日へフォーカスする。実勤務分・確認根拠の保存、確認済み休日は0分、未確認日は空欄、保存後に再計算する手順を示す。すでに保存済みの場合も、この案を公開する前に再計算が必要であることを明示する。
- 必須条件違反: 検証器の確認コードに対応する日本語の条件、特定できる対象者・日付、修正手順・画面への移動を示す。未知のコードは原文を保持し、原因を推測せず再計算・調査を案内する。詳細のないINVALIDも詳細不明として表示する。
- 古い案: サーバーのstale、凍結入力のstale、画面で確認した入力版不一致を反映する。条件と固定・編集内容を確認して再計算し、新しい案を選ぶ手順を示す。ボタンは計算ボタンへ移動するだけで、自動計算しない。
- 独立検証が未完了・取得不能・未知の状態: 履歴不足や必須条件違反と断定せず、実際の検証状態と完了確認・再取得・再計算を案内する。

2026-10-17追加：複数の理由や違反が再計算を案内する場合も、「計算ボタンへ」は理由の説明の後に共通で1つだけ表示する。各理由・確認コード・ほかの修正先は保持する。

修正先への移動は未保存入力の確認を通す。対象月・チーム・企業が変わると履歴の移動先を引き継がない。削除済みなど現在のスタッフ一覧にない対象はID付きの表示にし、最新履歴APIのrequired/recordsに含まれる本人を選択できるようにする。最新履歴の対象に含まれない場合はその旨を表示し、別人を自動で選んで入力させない。

## 保持する条件

公開時の現在条件による独立再検証・権限・版競合・必須条件の拒否は変更しない。人数・役割の不足は必須違反と分け、検証済みかつ不足確認済みの案の公開操作を維持する。修正ボタンは条件変更・履歴保存・計算・公開を自動実行しない。DB migration・API追加・Container更新は不要。

検証・反映記録（過去の私有資料・公開対象外）へ結果を記録する。
