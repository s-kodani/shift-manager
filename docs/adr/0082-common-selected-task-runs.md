# ADR 0082: 選択中の業務の継続量を共通で表す候補

2026-10-14。R-01。状態：技術候補・通常未採用。

各枠で厳密に一つの業務を選ぶ既存条件を使い、業務ごとの累積変数を選択中の業務の累積変数一つへ置き換える。前枠と業務が一致するBoolを全業務の選択literalに結び付け、変更境界と最後で該当業務の最低継続量を検査する。異なる最低量・0も扱う。inactive枠のcarryを維持し、休憩・研修・会議は長さ0、準備・移動は既存の長さで数える。

対応は旧モデルの選択中業務の累積値が共通値、非選択業務の累積値が0。旧モデルが省略していた最低量0の補助値は共通計算へ拡張する。候補・勤務量・固定／取消・役割・目的順序は変更しない。CP protoは異なるため同一protoを根拠にせず、手計算全列挙と独立checkerで比較する。

別案の業務候補削減や時間丸めは採らない。業務ごとの元表現は通常経路と比較用に残す。診断`mvp-joint-common-run-v1`だけcalendar／compact／shared／commonを有効にし、350万変数の診断ガードを使用する。通常common=False・100万ガード、内部120秒、CPU1／6 GiBを維持する。

計画（過去の私有資料・公開対象外）に事前の実行上限を記載し、実施結果（過去の私有資料・公開対象外）で等価性・性能・採用判断を分ける。変数減少だけで500人や全SDK／UIの受入を合格にしない。

Cloudflare追加0、最終一括、定期backup保留・30日、試験導入範囲外を維持する。
