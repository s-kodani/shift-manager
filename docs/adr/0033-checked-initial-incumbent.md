# ADR 0033: 限定した初期探索から全候補の本探索へ検証済み案を渡す

2026-10-12。状態: **CLIの技術候補を実装・検証中。製品の既定方式への採用と実Cloudflare検証は未完了。** 製品条件、勤務候補、段階目的、独立チェッカーを維持する。

[ADR 0032](0032-experimental-coverage-hints.md)の部分ヒントでは、複雑101人・30秒と500人・120秒で案を発見できなかった。全制約を満たす初期案を得る工程を、元問題全体の最適化・不可能証明と区別して追加する。

`balanced-incumbent-v1` は同じ貪欲ヒントから始め、予算の最大10%でCPSATの充足問題を解く。この呼出しだけ `fix_variables_to_their_hinted_value=true` とし、勤務・業務・役割の初期値を固定する。元モデルに固定制約を追加せず、別の本探索ソルバーはこの設定を使わない。本探索には全勤務・業務候補を残す。元モデルに存在する全必須条件を、限定探索でも省略しない。

限定探索が返す配置を独立チェックし、VERIFIEDかつモデルとチェッカーの目的ベクトルが一致する場合だけ初期案として保持する。履歴不足、必須違反、評価不一致は初期案として採用しない。限定探索のINFEASIBLE／UNKNOWNは元問題の判定に使わず、残り予算で元モデルを探索する。

初期案の全変数値を本探索のヒントへ渡す。段階ごとの既知案の達成値を有効な上界とし、先行値を悪化させずに次の目的を解く。新しい案が辞書式に悪ければ保持案を置き換えない。限定探索の最適性を本探索の下界として使わず、全体OPTIMALは元モデルの全目的段階がOPTIMALの場合だけにする。本探索で新案を発見できなくても、元モデルの全条件を満たす検証済み初期案がある場合はFEASIBLEとして返し、段階のUNKNOWN等を別に保存する。最後に配置から再検証する。これは[最適化仕様11.2](../shift_management_optimization_model.md#112-探索手順)の有効案保持に対応する。

共通の段階処理も修正する。後段で未証明の上位評価を改善したら、次の段階では改良後の実値を全先行目的の上界として更新する。最初の段階終了時の古い値だけを保護して、改善を失うことを防ぐ。この保護と辞書式の保持は従来方式にも適用する。旧コミット7a89460の従来方式に対する反例検査が失敗し、修正後は3方式で反例を拒否することを確認する。

目的が整数0の場合、保護制約から新しい定数変数が生成されることがある。これは直前のソルバー応答に含まれないため、確定した単一点domainからヒント値を補う。未解の新しい非定数変数を応答外の値で埋めない。全業務不適格・月最低量0で全月休日が合法なケースを確認する。

限定探索の範囲・状態・予算・検証・採用有無・初期目的は `metrics.initialIncumbent` に記録する。既定方式は `legacy-first-v1`、製品HTTP予算20秒と公開判定は維持する。初期案は外部の手書き比較案から取得せず、実入力と汎用ヒントから生成する。

参照: [OR-Tools v9.15のパラメータ仕様](https://github.com/google/or-tools/blob/v9.15/ortools/sat/sat_parameters.proto)。実ロック9.15.6755のPythonパラメータと小規模全列挙で動作を確認する。固定した探索で解けないことを元問題全体の解なしとしない。実測・残課題（過去の私有資料・公開対象外）を参照する。
