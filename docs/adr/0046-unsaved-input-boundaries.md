# ADR 0046: 未保存入力と応答不明の画面境界

日付: 2026-10-12。状態: 製品画面へ実装、限定したローカル受入を確認。全画面・実端末の受入は継続する。

## 判断

認証後のWorkspaceに共通の未保存状態を設け、企業・チーム・月・画面、計算履歴と編集元の変更、ログアウト、明示的な読み直しを保護する。確認を中止した場合は状態変更・新しい要求を開始しない。同じ画面・同じ対象の選択と、編集を保持する月間／日別／結果タブは破棄操作にしない。

レジストリに置くのはフォームのopaque ID、dirty／pendingフラグ、受領時の解除コールバックだけで、入力値や資格情報を新たに永続保存しない。制御フォームは追加・削除を含む入力の比較、非制御フォームは入力イベントと確認済み保存を使う。CSV選択も登録する。

1つの保存でほかのフォームが再読込される場合は、送信前にほかの未保存入力を確認する。送信元のフォームは自分の保存から除外する。Reactのsubmitハンドラーの同期区間だけにこの許可を限定する。captureからbubbleまでのmicrotaskで保持すると、実ブラウザーではbubble前に許可が消えるため使わない。

保存の拒否・応答不明でdirtyを解除しない。通常の共通保存は応答と後処理が完了した場合だけ送信元を解除する。同じ値を保存した場合にも解除し、ほかのフォームのdirtyを消さない。応答不明の再送には元のMutationと操作ID・送信元を保持する。

処理中・応答未確認の本人提出、受付、固定解除、取消、共通保存ではアプリ内移動を止め、同じ操作の照会／再送を残す。ページ再読込・閉じる操作にはbeforeunloadを使う。初回変更要求・権限失効に伴う認証終了は業務上の拒否を優先する。

## 検証と制約

実施記録（過去の私有資料・公開対象外）でネイティブ確認、選択を制御したブラウザー試験、注入した409／通信断、実workerdの同ID保存を分ける。既存の確定仕様、D1の版競合、独立検査、締切・バックアップ保管期間を変更しない。

beforeunloadの表示・文言・閉じる操作はブラウザーに依存する。入力の自動保存や、ブラウザーを閉じた後の未保存内容の復元を保証するものではない。全業務フォーム・複数企業／チーム・実端末の通し受入とG1は未完了。
