# ADR 0043: 稼働分の枠別索引と工程別計測

- 日付: 2026-10-12
- 状態: 実装・ローカル同値性検査済み。遠隔・性能受入は実施記録で別判定する。
- 対象: A1／WP-03。製品仕様・全候補・段階目的・初期探索予算は変更しない。

## 判断

勤務候補ごとの元の稼働分集合から、業務枠ごとの分数と最初の稼働分を一度作り、同じ日・候補の業務構築で再利用する。枠内分数・過去に稼働したか・切替先が枠開始から稼働できるかを、この索引で求める。準備の連続区間は元の分集合への包含で検査し、容量・役割・継続の分単位区間も維持する。索引は個々の構築内だけで使い、ジョブ・企業をまたいで共有しない。

旧方式は同じ分集合を枠・切替元／先ごとに走査・整列していた。101人のcProfile診断でこれを確認した。ANDの表現変更や候補削減は今回行わない。休憩を固定へ変える、業務配置を固定する、勤務最低量を緩める、7／10分を30分へ丸める処理は追加しない（Q92・Q122〜127）。

## 同値性と計測

元の整数分集合を期待値とする断片集合の全列挙、小規模の独立チェッカー全列挙比較、既存の固定・休憩・役割・継続・取消・段階保護検査を実行する。101／500人では初回CP呼出し直前のモデルとヒントをbinary exportし、修正前後の入力・バイナリ・変数・制約数の一致を調べる。これはその入力の構築同値性であり、CPを実行しないexportを実行可能案や全入力の性能合格に数えない。

`phaseTimings.seconds`を入力検証、候補事前処理、候補構築、業務、勤務ルール、目的、初期ヒント、初期実行可能性確認、競合ヒント／確認、本探索、最終検査に分ける。`modelBuildSeconds`はcandidates／duties／rules／objectivesの構築工程の合計で、候補事前検査・ヒント生成・探索を含めない。工程時間にはその工程の準備処理も含み、候補なしの事前処理時間はチェッカーを呼んだ証拠ではない。`initialFeasibility`等はCPだけの時間ではなく、抽出・独立検査・ヒント更新も含む。CP単体の時間は従来のincumbent／stagesを参照する。

途中終了でも計測を残し、`modelBuildComplete`と`lastPhase`で未完了を区別する。従来の`prepareSeconds`は累積時間として維持する。独立検査VERIFIEDだけでCP採用済みとは表示しない。UNKNOWN／NOT_RUNと全体のINFEASIBLEは引き続き別扱いとする。

## 保留

構築時間短縮と最終応答時間・解の質の改善を別に評価する。単一の架空条件、Macローカル、cProfileの診断、CPなしのexportをCloudflareの性能達成へ読み替えない。通常PoCはmvp-joint-v1／v4／120秒を維持し、保存候補方式の通常採用、反復品質・資源・通常業務の遠隔全導線・G0〜G2／現場受入・計算全体5分は別に残す。定期バックアップの有効化保留、30日保管を維持する。

実測・ソース・範囲は実施記録（過去の私有資料・公開対象外）に記録する。
