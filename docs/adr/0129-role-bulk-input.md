# ADR 0129: 役割の必要人数の期間一括入力

2026-10-17。ユーザー依頼「役割の必要人数も一括登録できるようにしてください」を反映する。

## 決定

需要管理の役割条件へ、開始日・終了日（両端含む）、曜日、毎日の時間帯、対象範囲（チーム全体／業務別）、役割、最低人数、比率の分子・分母を指定する一括入力を追加する。選択中の暦月内が対象。役割の登録単位は毎日の時間帯ごとに1件であり、需要の配置枠へは分割しない。チームが60分配置でも役割条件の端点は既存と同じ30分単位、終了2400を許容する。

最低人数・比率は明示入力する。最低人数は0〜500、分子0〜10000、分母1〜10000の整数で、空欄を0にしない。比率を使わない場合は0/1を明示する。Q61〜Q63の対象範囲、一般業務の実稼働人数を使う比率、最低人数と比率の最大値を採用する計算は維持する。企業の端数処理・チーム／業務の評価順序（Q122）も変更しない。

プレビューに対象日数と追加／上書き／保持件数を表示する。同じ日付・対象範囲・役割・開始・終了の既存条件は、初期選択で保持する。上書きを選ぶと最低人数・分子・分母だけを変更し、既存IDを維持する。別の日付・範囲・役割・隣接する時間帯と、需要・予定は維持する。チーム全体のnullと、文字列の業務名nullは区別する。

同じ日付・対象範囲・役割で一部だけ時間帯が重なる条件、同一時間帯の重複条件は、保持／上書きのどちらでも反映前に拒否する。該当日・既存時間を示し、同じ時間帯の指定または個別編集を案内する。既存区間の自動分割・削除や重複保存は行わない。

プレビュー後の条件／役割行の変更でプレビューを無効化する。反映は月次フォームへの反映で、「この月の入力を保存」で一括永続化する。需要と役割それぞれの編集中状態を保護し、どちらかの未反映条件が残っていれば保存を拒否する。役割未登録時は一括入力を表示しない。末尾ボタンの横並び・間隔は維持する。

## 実装・検証

需要と役割で対象日付の厳密検証・UTC日付展開を共通化する。API契約・DB・最適化モデルは変更せず、既存月次保存の権限・版競合・再送・原子性と独立検証を維持する。実施結果（過去の私有資料・公開対象外）を参照。
