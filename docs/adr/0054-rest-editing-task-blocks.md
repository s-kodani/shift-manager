# ADR 0054: 手動休憩編集で実稼働のある業務枠を再構成する

日付: 2026-10-12。確定製品仕様は変更しない。対象はWP-06／Q82・Q92・Q124、休憩・予定・取消の実稼働区間。

## 再現と判断

資源制限付きの実SDK・実画面試験で、架空500人の検証済み案からスタッフ0001の10月2日を休日から09:00〜12:00の勤務へ変更し、09:30〜10:00の自動休憩を指定した。勤務不可09:00〜09:30に理由付き例外を付け、勤務パターン・出退勤・休憩だけを明示固定した。

旧画面は休憩開始／終了と勤務分だけを更新し、09:30枠の業務を残した。独立チェッカーは`PHANTOM_TASK`で400／DRAFT_INVALIDとして保存を拒否した。保存ガードを緩めず、手動編集で稼働のない業務枠を生成する問題を修正する。

## 実装と不変条件

パターン変更と休憩変更で同じ枠再構成を使う。出退勤から30分／60分の枠を列挙し、休憩・取消・本人の予定を分単位で除いて、稼働が1分以上ある枠だけを残す。残る枠の既存業務・役割を保持し、新しく稼働する枠は既存パターン変更と同じ初期業務・役割なしとする。新しい配置も保存前に独立検証する。

勤務時刻・休憩種別・取消・明示固定・例外理由・分単位の役割区間は勝手に変更しない。部分稼働枠を全削除したり、予定を勤務分から除いたり、必要休憩量を変更したりしない。自動休憩の量・区間・全勤務条件の適否は、従来どおり保存時のサーバー検査に従う。パターン固定休憩と明示固定休憩への変更は拒否する。

内部モデルだけの確認と実チェッカーの合格を区別する。実施記録（過去の私有資料・公開対象外）で修正前の実測・保存拒否、修正後の回帰、500人計算の未発見により実画面保存・固定再計算・取消／再配置が未実行であることを分ける。Cloudflare追加試験は最終一括まで行わず、定期バックアップ有効化保留・30日保管を維持する。
