# ADR 0023: スタッフ番号照合と認証・契約の原子的なCSV反映

2026-10-11。状態：Q100／Q101のCSVを限定実装し、ローカルWorker/D1/R2と実Dockerで検証。後続の専用Cloudflare検証（過去の私有資料・公開対象外）で0019・コード・最新資産を反映し、実D1の原子性／認証／競合と100新規行を確認した。一般性能・全受入は未完了。

## 判断

MVPの試験チーム向けCSVを、既存スタッフの更新と新規スタッフの発行へ接続する。照合キーは企業内のスタッフ番号で、氏名・メールでは照合しない。同番号が他企業に存在しても別人とし、他チームへの移動や複数担当範囲で共有する本人アカウントの変更は、この取り込みでは拒否する。管理者が確認する行を曖昧な名寄せで反映しない。

UTF-8の16列、1MB・100データ行を1ファイルの上限とする。これは今回の取り込み方式の境界であり、試験チームの人数・製品の対応人数を変更する判断ではない。企業・雇用区分・個人の既存検証を通し、個人ルール7列の全空欄をnull、明示0を0として扱う。業務ID・習熟度・資格と適用月を検証する。番号／メールのファイル内重複は全該当行を除外する。

読み取りだけのプレビューを、操作者・企業・チーム・適用月・入力版・参照設定版・既存本人・CSV原文のハッシュへ結合する。反映時に再構築し、版競合やプレビュー改変を拒否する。単一D1 batchに、親の取り込み操作、認証／スタッフ更新、各スタッフの通常の契約入力操作と不変版、監査、除外診断を含む不変記録を入れる。入力版は元版+1+正常行数。Q118の再検証要求は既存トリガーで同じトランザクションへ記録する。公開勤務・元の証明は変更しない。

新規アカウントは既存Better Auth用の発行処理でハッシュを作り、初回変更必須とする。既存本人ID・パスワード・有効／無効・権限は保持する。メール変更時は確認済みフラグを戻し、旧セッションと旧宛先の再設定トークンを失効させる。使用中の別アカウントのメールは奪わない。平文初期パスワードは最初の確定応答だけに含め、DBの取り込み記録・監査・再送応答には入れない。応答不明なら同じ操作ID・同内容の結果を確認し、新規の操作へ自動切替しない。

## 代替案・技術候補

メール照合はQ100に反する。行単位で順に確定する方式では、後続のDBエラーで認証・契約が一部だけ変更される。プレビューをクライアントだけで判定する方式では権限・参照・版の競合を防げない。平文パスワードの永続保存による再表示は採用しない。再設定メール・管理者の利用者運用はWP-01の残作業と接続する。

既存のReact・Better Auth 1.7.7・D1を拡張し、CSVライブラリや認証方式を変更していない。D1の[batch仕様](https://developers.cloudflare.com/d1/worker-api/d1-database/)と[制限](https://developers.cloudflare.com/d1/platform/limits/)を2026-10-11に確認した。Paidは1呼び出し1000 query、Freeは50、batch全体も30秒制限の対象。100行のローカル成功を、実CloudflareのCPU・DB時間やFree互換性の確認とは扱わない。

## 実施結果・未検証

実施記録（過去の私有資料・公開対象外）に、13専用試験、画面中止／反映／同ID再送、実Dockerの2名計算と独立チェック、範囲と未検証を記録する。100新規行の原子反映・再送をローカルで確認した。後続の専用Cloudflare検証で100新規行の単発反映を確認した。異なる条件の反復性能、共有アカウントの個別変更・所属移動、Excel、現場受入は未検証または後続実装。制限を回避するための分割確定や必須条件の緩和は行わない。
