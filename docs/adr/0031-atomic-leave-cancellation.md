# ADR 0031: 休暇承認・欠勤取消の原子確定

2026-10-14補足：[ADR 0073](0073-partial-event-cancellation-refusal.md)でQ97の未割当ケースを確定停止・管理者の事前配置調整／別公開後の再確認に決定。以下の「ユーザー確認中」は先行試験時点の記録。

2026-10-12。WP-08、Q69・Q96〜97・Q121・Q124・Q128〜131。状態：限定実装、ローカルD1／R2と実Docker Containerで検証。確定仕様は変更しない。

## 判断と由来

仮検証とは別の操作IDで、最新の条件から取消候補を再構築し独立チェッカーへ渡す。DOの排他と実プロセス停止確認後、入力・公開・受付・編集の版と現在の権限を再照合する。VERIFIED、違反なし、必要履歴ありを必須にする。人数・役割の通常不足だけは管理者の明示確認で確定できる。固定が残る勤務、最低勤務量違反、自動休憩の不一致、未割当は拒否する。

元公開文書と入力版を保持し、取消の由来を持つ新公開版をR2へ保存する。元の計算／編集参照は祖先であり、取消結果を新しいソルバー出力と扱わない。新証跡は親公開ID・digest、受付ID、候補digest、検査対象の入力・版履歴、参加解除を結び付ける。管理者は由来を確認でき、本人への公開読取は従来の本人勤務だけのprojectionを維持する。

## D1の原子性

migration0025で取消操作・参加解除・本人通知の不変記録を追加する。単一batchで新公開版、全勤務、固定情報、参加解除、監査、公開イベント・通知、commitを保存する。commitに伴って公開head・企業版と再検証状態が更新される。失敗は全体をロールバックし、条件付き更新0行を成功扱いにしない。

既存の受付headと予定入力の原本を破壊的に作り替えない。`leave_effective_head`はcommit済み取消を重ね、APPROVED／CANCELLATION_CONFIRMEDと受付版を返す。`leave_all_notice`は受付と確定の通知をまとめる。今後の状態照合もこれらを使う。生の`leave_head`のPENDING／REPORTEDだけを現在の受付状態と解釈しない。

予定は、当該入力版・本人・イベント・日時に対応したcommit済みの参加解除を重ねて有効登録を返す。次のスナップショットへ解除履歴も含める。別の予定入力版を保存した場合は新たな原本として扱い、取消と重なる参加の再登録は既存の登録時検査で拒否する。

SQL guardも権限・版・親公開・固定解除・全勤務と通知の保存を検査する。取消以外の本人のパターン・出退勤・休憩、他の勤務を変えない。分単位の取消集合は元の取消と申請区間の和集合に一致させ、休憩との二重控除を防ぐ。対象予定参加の全解除を数でも照合する。

## 応答不明と別公開

同じ操作ID・凍結した要求は最初のreceiptを返す。変更した要求は409。ブラウザーは送信前に操作ID・元公開ID・各版・不足確認のみをsessionStorageへ保存する。資格情報、氏名、理由、勤務、検証結果を保存しない。応答不明は同IDのGET照会へ進み、未発見だけでは再送しない。再読込後に受付が承認済みでも照会入口を保持する。tabを閉じる／storage消去をまたぐ端末復旧は未検証で、受付履歴・監査による管理者確認を残す。

取消の確定は現在勤務へ即時反映する。その後の通常計算は取消済みの出退勤・休憩を保持して業務だけを再配置する。計算成功では公開版を変えず、管理者の別の公開操作で更新する。

Q97の参加全解除で取消外の時間が未割当になる場合の確定操作はユーザー確認中。そのケースはWAITING違反で停止する。自動的な担当追加、最低量の削減、休憩種別変更を行わない。これは未解決範囲であり、WP-08全体の受入完了ではない。実施結果（過去の私有資料・公開対象外）と操作手順（過去の私有資料・公開対象外）を参照。
