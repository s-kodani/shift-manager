# ADR 0098: 複雑な500人条件の性能改善を後続課題へ移す

- 日付: 2026-10-14
- 状態: ユーザー決定
- 根拠: 複雑な500人条件の処理量とメモリ余裕は厳格な制約ではないためMVP範囲外とし、現時点の性能を示して今後不都合があれば対応する。案の品質と通常経路への反映は継続する。

## 判定範囲

5業務／10勤務パターン・500人のモデル準備／読込み時間短縮、探索時間の確保、6 GiB上限に対するメモリ余裕の改善・反復保証は今回の完成条件から外す。性能の悪さや計測時の時間切れだけを理由にこの課題をMVPの停止条件へ戻さない。追加性能実験を無期限に続けず、後続で実際に支障が出た条件の証跡に基づいて対応する。

R-01の対象は案の品質と通常ジョブへの接続・採用判断に絞る。同じ入力・評価順序で不足／希望／余剰を比較し、勤務・休憩・固定・取消・履歴の必須条件を独立checkerで検証する。改善候補のmodel、hint、全候補、段階目的、状態分類を維持し、検証済みの候補だけを通常経路へ接続する。最適解証明や希望完全充足を新しい必須条件にしない。通常設定の採用と候補接続の実装、実計算／全SDK／画面の受入は区別する。

原子更新・版競合・企業／チーム境界・重複防止・故障時回収・独立検証・公開後の固定維持は対象のまま。性能を範囲外にしても、無効案の保存／公開、時間切れをINFEASIBLEへ読み替える処理、無制限再送を許容しない。資源上限・計算予算・製品設定値を拡大／制限しない。

## 現時点の性能と制限

全値はローカル1 CPU／6 GiB／追加swapなし。Cloudflare性能の証明ではない。異なる入力・profileの値を同一条件の改善率にしない。

| 条件／方式 | 実測 | 結果と制限 |
| --- | --- | --- |
| 3業務／2パターン、101人、30／60分、通常方式・各2回 | solve HTTP約108.5〜108.7秒、別check約2.0〜2.5秒 | 全4回FEASIBLE／別check VERIFIED、希望未充足80。全体の希望最適性は未証明 |
| 同条件500人、30／60分・各2回 | solve HTTP約107.0〜123.6秒、別check約9.6〜11.2秒、最大peak約5.26 GiB | 全4回FEASIBLE／別check VERIFIED、希望未充足379、OOM0。全UI時間・全入力保証ではない |
| 5業務／10パターン、101人、calendar候補 | solve HTTP113.951秒、別check2.547秒、peak約4.54 GiB | FEASIBLE／別check VERIFIED。役割先行の辞書式評価は参照より良いが一般不足は増加、希望未充足101 |
| 同じ複雑500人の保存modelを復元、layout解放診断 | 読込み・検証等約49.1秒、solve工程90.299秒で終了、peak6,404,845,568 bytes | OOM0、上限余裕37,605,376 bytes。seed UNKNOWN→本探索で期限、有効案なし。model準備を含まない診断で通常性能値ではない |

通常反復（過去の私有資料・公開対象外）／5業務10パターン（過去の私有資料・公開対象外）／最新の解放診断（過去の私有資料・公開対象外）。以前の複雑500人のOOM失敗・候補未採用の証跡も保持する。未検証を成功扱いしない。

## 後続対応と既存方針

支障が出たら入力版・設定・profile・人数／業務／パターン・時間・メモリ・終了状態を記録し、ローカルで再現して対応する。R-05運用・メール・AI、R-08試験導入の範囲外、最終Cloudflare一括、定期backup HOLD／30日は維持する。既存コード・診断入口・原本・秘密管理を削除しない。
