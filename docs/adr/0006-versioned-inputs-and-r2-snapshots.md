# ADR-0006: 月別入力の版とR2スナップショット

日付: 2026-10-10。状態: WP-02の限定実装・ローカル／専用Cloudflare試験済み。MVP完成・G0通過ではない。

## 対象

設計0.10のQ81・83・87・99・110・118・119・122・127と、実装計画WP-02／04を参照する。製品仕様は変更しない。今回は未公開の計算入力を固定する。公開済みシフト・取消・固定・実履歴の保存は後続工程である。

## 実装した判断

- 企業共通ルール／契約／習熟度段階、雇用区分別ルール／契約、個人契約／追加ルール／スキル／資格、チーム設定、月別需要／予定／役割条件、本人の月別勤務不可／希望を別々の追記式版で保存する。企業共通・雇用区分は企業管理者だけが変更でき、担当チームの入力は企業管理者／担当チーム管理者が変更できる。今回の本人入力APIも管理者用で、本人提出・締切・受付再開は未実装。
- 設定と契約は対象月以前の最新の適用開始月、その開始月の最新の作成版を選ぶ。需要・予定・希望は対象月の版だけを選び、前月を流用しない。希望未提出は希望なし。必要な設定・契約・需要版の未登録は失敗にする。
- 計算入力全体をクライアントから受け取らず、サーバーで保存版を結合する。数値ルールは企業・雇用区分・個人の全件を保持し、契約の曜日・時刻は共通部分を使う。個別設定で共通ルールを緩めない。最低習熟度と能力係数を分け、係数は企業共通段階に対応する業務設定から導く。直接需要の0と未設定nullを保持する。全体優先はチーム設定1つ、役割方式は業務／チーム範囲、端数処理は企業設定から導く。
- APIの曜日はカレンダーと同じ日曜0〜土曜6。Python契約の日曜6／月曜0へ明示変換する。時刻は日本時間の日内整数分、半開区間。出退勤／休憩／業務境界の30分整列と、7分等の準備・移動を区別する。
- 保存時に入力形・範囲・参照・重複・既知の矛盾を検査し、スナップショット時も選択版の組み合わせを再検査する。予定は対象者の全時間参加が可能な勤務パターン・契約・休憩・勤務不可かを検査する。この事前検査は月全体の実行可能性や制約検証の証明ではなく、ソルバーと独立チェッカーで追加検証する。
- D1の企業版と操作IDを共通の競合基準にする。操作INSERTのトリガーが現在の権限・初回変更状態・期待版を検査し、版・入力・監査を同じbatchで確定する。SELECT時点で許可されても、確定時に失効していれば拒否する。再送は同じ要求・実行者・対象の場合だけ既存結果を返す。
- 大きな入力は非公開R2へ先に保存する。試行ごとに別のランダムキー、作成専用条件、SHA-256を使い、D1で入力版・サイズ・ダイジェスト・参照キー・採用した設定版一覧を原子的に確定する。スナップショット作成自体は入力版を増やさない。同時再送が勝者のオブジェクトを上書き／削除しない。
- R2とD1には共通トランザクションがない。D1で確定できなかった／確定が不明なアップロードは孤立オブジェクトとして残り得る。単一の未存在読取を根拠に削除しない。敗者の同一操作が確定済みの別オブジェクトを参照していると判明した場合だけ、自分のアップロードを削除する。猶予期間と参照確認によるGCは未実装。
- 読み出し時に権限・企業／チーム境界、サイズ上限、実バイト長、SHA-256、入力内のID・月・版を検証する。過去入力は当時のバイト列を保持し、企業版が変わればstaleと表示する。requireCurrentは読取時点の検査であり、後続ジョブの結果採用・公開時にも原子的な版検査が必要。
- JSON Schemaからビルド時に静的Zodコードを生成する。WorkersでevalやFunctionを実行しない。未対応の検証キーワード・参照の併記条件・重なるoneOf等は生成失敗にする。生成ファイルの陳腐化をtypecheckで検出する。Python側のJSON Schema・意味検証も継続する。

## 候補・代替案・未検証

全入力をD1の単一JSONへ置く案は行サイズと500人の拡大余地を制限するため、R2本体＋D1参照を第一候補として実装・試験した。企業版は簡単に一貫性を守れる一方、担当外チーム／将来月の更新も競合・staleにする。版の細分化は後続で検討する。

現在の入力契約はA1 multi-task-v1候補の範囲（2000〜2099年、最大500人・5業務・10パターン・2役割）を使う。これは技術試作の上限で、製品仕様の年範囲を新たに決めたものではない。HTTP入力は2,000,000バイト、スナップショットは4,000,000バイト以下。会社・スタッフ発行等は既存16 KiBを維持する。大規模入力の処理時間・メモリ・上限妥当性は未測定。

実履歴は未接続で、履歴なしを過去の休日・0時間へ捏造しない。今回はdraftだけで、公開元・固定・例外・取消を外部入力で置き換えられない。WP-06／07で権威ある保存先から結合するまで、製品の公開／再配置へ接続しない。公開済み月への設定適用と再検証、CSV、本人提出、非同期ジョブ、R2の復旧・GC・保持期間は残る。

## 技術資料と結果

Cloudflare公式の[R2 Workers API](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/)、[R2 CLI](https://developers.cloudflare.com/r2/reference/wrangler-commands/)、[D1 batch](https://developers.cloudflare.com/d1/worker-api/d1-database/)とWrangler 4.149.0の設定・生成型を確認した。R2の作成専用書込・チェックサム・D1参照確定は、実施記録（過去の私有資料・公開対象外）のローカル／実環境結果で区別する。
