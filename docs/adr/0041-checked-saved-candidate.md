# ADR 0041: 保存済み案と自動初期案の比較

2026-10-12。状態: 検証用プロファイルを実装。通常PoCでの採用は保留し、`mvp-joint-v1`を維持する。実施記録（過去の私有資料・公開対象外）。製品仕様・全候補・固定対象・段階目的・独立チェック・150秒通信期限を変更しない。定期バックアップ有効化の保留と30日保管を維持する。

## 問題と選択

ADR 0040の500人の登録済み入力では、固定再計算の最終combined 258,000が独立検証済みの手動案224,000より悪い試行があった。保存済み案を探索の候補として再利用する。ただし過去の証明だけでは最新条件の妥当性も、CPモデルでの実行可能性も示せない。

最初の101人実験では、保存済み案だけの初期化はcombined 232,000を保持し、通常自動初期案の0より悪かった。その記録を保持し、保存案と自動案を同じ限定探索時間枠で比較する方式へ修正した。常に保存案を優先する方式は採用しない。

1. 最新入力を既存の厳格な契約で検査し、保存案全体を独立チェッカーで再検査する。`VERIFIED`以外は候補採用を拒否する。
2. 勤務パターン・出退勤・休憩の候補、業務枠、正確な役割区間をCP変数の開始値へ対応付ける。中断した枠は内部の前業務を引き継ぐ。負のBool literalと暗黙の役割なしを扱う。現在のモデルで表せない分単位の境界は丸めず、候補採用を拒否する。
3. `fix_variables_to_their_hinted_value`を限定した実行可能性確認だけに使う。実CPが案を得て、抽出した案の独立検査とCP評価ベクトル、および元候補を最新条件で検査したベクトルが一致した場合だけ保持する。
4. 通常の自動初期案も、残る同じ限定時間枠でCPと独立検査へ通す。辞書順で良い案だけを保持する。二つのCP呼出しへ元の時間配分を二重に付与しない。
5. 本探索は全候補を維持し、業務を固定する制約を追加しない。採用した案の上位評価を保護して段階探索へ進み、最終案を再検査する。限定探索のOPTIMAL／INFEASIBLEを元問題全体の証明へ流用しない。

CPの開始値固定と探索停止の意味は[OR-Tools公式パラメータ定義](https://or-tools.github.io/docs/cpp/sat__parameters_8proto_source.html)を参照し、実際の互換性は固定依存9.15.6755の試験で確認する。Workerでは既存の上限付きR2読取・ハッシュ確認・権限確認・別check・停止後の終了を維持する。[Workers公式の実装指針](https://developers.cloudflare.com/workers/best-practices/workers-best-practices/)を参照したことと、実Cloudflareでの受入を区別する。

## 通信・版・有効化範囲

バックエンドだけが選ぶ任意プロファイル`mvp-joint-seed-v1`を追加する。120秒／v4を維持し、`/solve`の`solve-seed-v1` envelopeで厳格な入力と任意の保存候補を別々に渡す。入力4MB、候補8MB、全体16MBの上限を設ける。従来の`/solve`と`/benchmark`の4MB上限、`/check`の16MB上限を維持する。予算・任意方式・追加固定などの注入を拒否する。

Workerはスナップショットが記録した下書きID／版だけを参照する。企業・チーム・月・管理者権限、R2保存内容のハッシュと現行headを既存読取で確認し、版競合では停止する。下書きの過去の入力版の証明は再利用せず、最新の厳格な入力で再チェックする。返答のプロファイル・予算・方式・候補参照が一致しなければ結果を保存しない。結果の入力ハッシュは候補を含めない最新の入力本文に対応し、候補元のID／版は別に保持する。

このプロファイルは専用の架空試験で明示して使う。`infra/wrangler.jsonc`の通常PoCプロファイルは変更しない。Cloudflareでの資源・停止・全導線と反復品質を確認する前に通常運用へ有効化しない。手書き参照案をソルバーへ組み込まない。

実施結果: 最終ソースの101／500人Python比較は両方式FEASIBLE／VERIFIEDで自動案の良い評価を維持した。登録済み500人の専用HTTP／Docker受入1ケースが合格し、固定再計算は最新条件で検査した保存案と同じ評価を保持した。この実Docker試行の追加自動案CP確認は時間枠0で未実行、本探索の改善・全体最適性は未確認。通常PoC採用、Cloudflare配備・反復品質・全導線は別に残す。
