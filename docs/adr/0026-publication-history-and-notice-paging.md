# ADR 0026: 公開履歴の版選択と本人通知の追加取得

2026-10-11。状態：限定実装・ローカル検証、専用非公開Cloudflare PoCへの配備済み。設計0.12の7.4／Q30・Q33、WP-07を対象とし、製品仕様を変更しない。

## 判断

通知は直近100件で打ち切らず、記録時刻と公開IDの降順で50件ずつ取得する。同時刻には公開IDで順序を確定し、続きは最後の組より古いものだけを返す。公開履歴も無制限取得をやめ、チーム・月内の公開版の降順で50件ずつ返す。51件目の存在から次カーソルを返す。取得中に新しい公開が追加されても、OFFSET方式のずれで既存の続きが抜けたり重複したりしない。

カーソルは検索位置であり権限を与えない。企業・チーム・本人IDは認証と所属から決め、取得後にも権限を確認する。部分指定・負数・指数表記・安全整数外の数値・不正UUIDを拒否する。履歴は管理者のみ、通知は本人のみ。既読更新も企業管理者またはチーム所属という参照権限と一致させ、保存済みの既読時刻を返す。同IDの再送で時刻を更新せず、条件付き更新0行と未読のままを成功扱いにしない。

版選択は保存済み公開オブジェクトの既存ハッシュ・参照照合を使う。画面は現在headと表示する版を分け、旧版表示で公開時の条件・日時・版を識別する。古い表示で現在のCSV・固定解除・現在条件再検証を操作させない。公開の競合判定に旧表示版を使わない。通知の対象月と公開IDから当時の本人勤務を開き、最新へ戻る操作を設ける。氏名の一覧をスタッフへ返さず、画面でも本人IDで勤務を限定する。

履歴の公開者ID・元版ID・時刻は既存記録を参照する。表示名は現在のuser.nameを使うため、「現在の表示名」と明記し、当時の氏名を後付けで捏造しない。表示だけの切替で新しい公開版・入力版・通知は作らない。

## 結果・代替案

実施記録（過去の私有資料・公開対象外）にD1／R2統合、実ローカルContainer、画面、Cloudflare配備を分ける。既存スキーマで実装し、migration・依存・計算制約を追加変更していない。OFFSET方式と一括無制限取得は採用しない。実環境での多数通知ページ操作・通信断・現場受入、取消確定との原子同期、運用復元は残る。

参照：[D1 prepared statements](https://developers.cloudflare.com/d1/worker-api/prepared-statements/)、[Workers best practices](https://developers.cloudflare.com/workers/best-practices/workers-best-practices/)。SQLは企業・チーム・本人とカーソルをバインドし、応答はno-storeを維持する。
