# ADR 0003: 複数業務のA1モデルとResend配送

日付: 2026-10-10。状態: A1実装判断とユーザー指定の配送サービス。MVP完成・G0採用・性能達成は未判定。

## 複数業務の技術判断

既存の `single-task-v0` を維持し、未対応入力を黙って解かない `multi-task-v1` を追加する。契約は整数分の半開区間、明示した能力尺度、業務ごとの適格性／能力、企業共通の役割丸め、業務・チーム範囲の役割方式、予定、切替ペア、固定対象、例外理由、公開元を持つ。能力尺度1000は架空データの設定であり、製品全体の採用精度ではない。

ソルバーは勤務・自動休憩候補と業務を同時計算する。各候補の出退勤・休憩・予定・取消、配置枠と全切替ペアの終了点を含む状態変化区間で集約する。候補を性能のために間引かず、役割は通常処理中の区間で1つを選ぶ。業務選択枠の途中の状態変化でも役割を計数できる。独立チェッカーは候補生成・モデルをimportせず、1分集合から勤務・準備・継続・役割・不足・希望を再計算する。

目的順序はモデル詳細仕様11章の合成案を実装し、小規模データで評価する。後段は先行値以下を制約として持ち、等式で未証明の改善を禁止しない。過去のv0実装もこの箇所を修正する。全段階の最適性が未証明ならFEASIBLEとし、前の案を保持する。構築中の期限／初期の100万変数ガードに達した場合はUNKNOWN／NOT_RUNで返し、条件矛盾とは扱わない。ガードは現モデルの負荷対策で、500人対応の完成ではない。

代替候補は勤務と業務の段階計算、候補間で共有する論理担当変数、密な1分モデル。現時点で最終選定していない。勤務・業務を分ける場合も、後段が配置不能なら勤務へ戻す。性能改善のための必須条件省略や待機状態は追加しない。

後続の実装改善: [ADR 0004](0004-shared-daily-task-state.md)で日別の業務状態・稼働マスクを共有し、初期探索ヒントを追加した。入力契約と独立チェッカーは維持し、追加計測（過去の私有資料・公開対象外）で実施結果を管理する。

A1結果は `BLOCKED_A1` のまま。固定なしの理由付き手動例外・製品保存／公開API・イベント登録の実現可能性・取消承認の原子更新は後続工程。取消済み公開元を入力できることだけで承認実装済みにはしない。

## Resendの決定と接続

ユーザーがメール送信サービスにResendを指定したため採用方針を記録する。製品のシフト通知をメールへ拡張しない。SDK依存を追加せず、Workersのfetchから固定した `https://api.resend.com/emails` へPOSTする。

APIキーはsecret、Fromは確認済みドメインのメールアドレスを非秘密設定として管理する。PoC／ローカルでは配送をdisabledとし、模擬配送を注入する。設定が不足する場合はユーザー検索前に一律拒否する。配送失敗でアカウントの有無によって応答が変わらないよう、再設定受付の応答を揃える。タイミング差・レート制限の運用評価は未完了。

URLのorigin・経路を検査し、認証が作ったトークンだけを `/reset` 画面へ渡す。同一メール内容をSHA-256で識別する冪等キーで、ネットワーク／5xxの再試行を最大1回行う。各要求5秒、429／その他4xxは即失敗。Providerの本文・認証情報・トークンをログへ転記しない。API受付成功と受信箱への配達完了は別で、実配送は未検証。

## 根拠・証跡

- A1の実施結果（過去の私有資料・公開対象外）
- [Resend送信API](https://resend.com/docs/api-reference/emails/send-email): Bearer認証、POST、From／To／本文。
- [Resend冪等キー](https://resend.com/docs/dashboard/emails/idempotency-keys): ヘッダーと再試行、保持24時間。アプリの永久冪等性を保証するものではない。
- [Cloudflare Workersの実装指針](https://developers.cloudflare.com/workers/best-practices/workers-best-practices/): 生成型、秘密値、await、期限付き外部通信。
