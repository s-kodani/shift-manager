# ADR 0019：公開時の固定証跡と現在の解除状態を分ける

2026-10-11。WP-08の前提工程。Q69の管理者による明示解除、Q92の勤務パターン・出退勤・休憩の固定対象を適用する。製品仕様は変更しない。

## 判断と実装

公開R2文書の固定・例外と当時の検証証明は不変とし、解除は別のD1履歴へ記録する。公開文書を書き換える案や、古い編集画面のチェックを外すだけで現在の公開固定を解除する案は採用しない。解除しても公開済みの出退勤・休憩・取消区間・業務配置を変更しない。

migration0017は公開固定のsource・lock・exception・seal、release・commitを追加する。新規公開は全勤務と固定メタデータの完全性を確認してから同じ公開batchを確定する。既存公開版は企業・チーム・公開IDとSHA-256を検査したR2証跡から全件を原子的にmaterializeする。部分的なsourceを有効にせず、seal後の追加・変更・削除を拒否する。元のR2文書と過去入力を再解釈して上書きしない。

解除は現在公開版・企業入力版・現在の管理権限を読み取り、選択したスタッフ・日付・固定項目だけを保存する。D1 triggerでも初回変更完了・利用権・担当管理者・現在head・期待入力版・未解除の固定を確認する。解除・監査・commit・企業revision・現在の再検証要求を同じbatchで確定し、失敗は全体をロールバックする。条件付き更新の0行を成功証跡に使わない。[D1 batchの契約](https://developers.cloudflare.com/d1/worker-api/d1-database/)とローカル実Workerdの故障注入を併用した。

同じ操作ID・同じ実行者・同じ内容の再送は当初のreceiptを返し、項目順序を正規化する。別内容・別実行者への流用を拒否し、再送でも現在の利用権を確認する。画面は初期状態で固定項目を選択せず、応答不明時は同じIDで確認する。

入力スナップショット、保存済み編集版の再計算、予定・勤務不可の登録検査、公開の再検証は現在の解除履歴を参照する。古い編集入力版より後に解除された固定を再導入しない。新しい入力のlineageへ解除IDと適用入力版を結ぶ。まだ有効な公開固定を、手動候補・保存・公開で暗黙に落とす操作は拒否する。固定解除後も公開後の時刻・休憩維持は独立チェッカーの必須条件として残る。

## 実施結果と未検証事項

実施記録（過去の私有資料・公開対象外）に、制御checkerによるD1統合試験と、実Dockerのチェック・自動再検証・再配置、実画面操作を分けて記録する。Workers・Containersの既存構成と依存版を維持し、新たな技術候補の採用・大規模性能の達成は判断していない。

この工程では休暇を承認せず、勤務取消を確定しない。次は現在の固定・条件・公開版を使う取消仮検証、最低勤務量・自動／固定休憩、予定参加解除・公開勤務・履歴・本人通知の原子同期を実装する。実Cloudflareの累積migration／配備、旧公開版の移行故障注入、実端末・大量データ・一連のTS-OPS受入は未検証。
