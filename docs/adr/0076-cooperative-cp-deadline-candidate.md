# ADR 0076: CP期限の協調停止を独立した技術候補にする

2026-10-14。R-01／TS-PERF。状態：候補実装・ローカル検証済み、通常設定へは不採用。製品の必須条件・希望採点・目的順序・公開判定を変更しない。

OR-Toolsの時間設定を硬い終了期限とみなさない。既存計測でCP内部の指定時間超過を観測したため、`mvp-joint-deadline-stop-v1`だけに期限監視を追加する。通常`mvp-joint-covered-off-hints-v1`の予算120秒・worker1／seed0・全候補・初期hint・段階目的をそのまま使う。モデルの前処理無効化・候補削減・月最低条件の緩和を代替としない。

公開`stop_search()`は非同期で、Python wrapperが生成される前の要求は無効となる。[OR-Tools 9.15の一次実装](https://github.com/google/or-tools/blob/v9.15/ortools/sat/python/cp_model.py)とローカル固定版9.15.6755を確認した。各solve呼出しに専用threadとEventを置き、呼出し予算を過ぎたら10ms間隔で停止を再要求する。solve終了・例外時にEventを設定してjoinし、次の呼出しに監視を残さない。予算0はsolveを開始せずUNKNOWNを返す。停止要求の失敗は明示的な実行エラーとし、解なしへ読み替えない。

戻り値はソルバーの実状態を維持する。探索停止時は独立checkerが既に確認した候補だけを保持する。初期のhint制限探索のOPTIMAL、全モデルでの各目的の証明、最終FEASIBLE、制約VERIFIEDを別々に記録する。停止要求時刻・回数・joinと実solver wallを証跡へ加える。

同源500人比較では641回の停止要求でもCP指定45.366秒に対してwall54.221秒となり、通常より時間超過を改善しなかった。通常への採用は行わない。協調停止はCP内部の全工程を一定時刻に中断する保証を持たない。外側のHTTP期限・所有コンテナの停止／回収を維持する。同一ソースimage・同入力・同資源での比較と未検証範囲は計画（過去の私有資料・公開対象外）および実施結果（過去の私有資料・公開対象外）へ記録する。厳密な時間保証を採用理由にしない。

Cloudflare追加配備／計算0。最終一括確認、定期backup保留・30日保管、試験導入範囲外を維持する。
