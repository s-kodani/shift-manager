# ADR 0027: 復旧用コピーの30日保管とD1／R2整合検査

2026-10-11。状態：保管期間はユーザー決定、手動取得・検査ツールは実装、復元の実施範囲は実施記録（過去の私有資料・公開対象外）を参照。WP-10／Q116〜117／TS-REC-02。勤務制約・承認・公開の仕様は変更しない。

追補：[ADR 0028](0028-remote-recovery-storage-and-monitoring.md)で遠隔保管・監視・期限削除を限定実装し、実試験した。以下の候補・未実装は手動取得時点の状態で、現在の結果は追補と区別する。

## 確定事項

ユーザー回答「バックアップは30日」により、MVPの復旧用コピーを30日保管する。勤務・監査履歴など原本の保存期間とは別で、原本へ30日の削除条件を追加しない。RPO最大24時間、サービス全体停止からRTO1時間の目標は維持し、今回の部分検証だけで達成済みとしない。

## 実装の判断

D1 SQLと、その復元点から参照される入力・計算結果・手動版・公開版・再検証のR2オブジェクトを一組として扱う。原本R2は不変参照を前提とし、SQLに存在しない孤立オブジェクトを復元点の必須対象にしない。新しい参照テーブルを検出した場合は未対応として停止する。SQLのサイズ／SHA-256、全テーブルの内容ハッシュと行数、スキーマ、外部キー、全オブジェクトのサイズ／SHA-256を検査する。活動中ジョブやRUNNINGの再検証を含む点は採用しない。

ツールの保管先はGit除外の`.cache/backups/<UUID>`。ディレクトリ0700、コピー・診断ファイル0600とし、端末とコミット証跡には資格情報・SQL値・オブジェクト本文を出さない。SQLには認証テーブルも含まれるため、通常ログやCI artifactへアップロードしない。単独運用のCLIロックを取り、取得／インポートの送信前にIDと状態を記録する。中断の経過不明時は同じIDを保持して照合し、タイムアウトだけで再送しない。

空の専用Cloudflare試験DB・R2だけをインポート先として許可し、元のPoC DB・元バケット・異なるアカウント／設定を拒否する。インポートSQLは元のSQLを保持したまま、全テーブル→索引→データ→トリガーの順へ並べ替える。内容・スキーマの一致と、外部キー有効の単一トランザクションでの投入を事前に検査する。制約やトリガーを復元後に省略する回避策は採用しない。

完成コピーの期限は完了時刻から30×24時間。`prune`は完成・検査済み・期限到達の専用コピーだけを削除する。期限直前、新しいコピー、未完了操作を保持し、原本D1／R2へ削除を送らない。未完了コピーの事故調査と終了処理は運営者の作業として残す。

## 技術候補と未検証事項

D1 PaidのTime Travelは30日以内の復元手段の候補で、SQL復元と別に実試験する。[公式Time Travel](https://developers.cloudflare.com/d1/reference/time-travel/)。R2の専用遠隔保管とライフサイクルによる30日削除、日次取得・失敗通知・保守モードは後続候補で、今回のローカルコピー取得を日次自動バックアップの完成と扱わない。[R2 lifecycle](https://developers.cloudflare.com/r2/buckets/object-lifecycles/)。

本番の復旧前にはWorker／Queues受付停止、Container実プロセス停止と永続フェンス照合、認証セッション失効、配送待ち・入力版・公開版の整合、業務APIの再開が必要。これらを今回のDB／オブジェクト照合で代用しない。大規模データ、認証／承認／取消まで含む停止・再開演習、原本履歴保持・運営者責任・遠隔コピーの保護は未完了。

代替案：D1だけのコピーではR2欠落を直せない。参照の検査なしで全バケットを複製すると、どのDB版に対応するか証明できない。元環境へ直接インポートする演習は採用しない。
