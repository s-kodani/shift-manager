# ADR 0135: 計算準備・スタッフ勤務・入力変更の表示場所

2026-10-20。ユーザー承認済みの画面整理計画に基づく。Q82・Q92・Q104・公開後の勤務維持と既存の権限・検証条件は変更しない。

## 決定

管理者の左メニューで「シフト計算の準備」を「シフト・計算結果」の直前に置く。`section=readiness`を既存のURL復元・所属判定へ追加し、企業・チーム・対象月を共有する。9つのチェックは完了も含めて常時展開する。需要枠は現行APIの先頭12件の例示を維持し、その例も展開表示する。計算開始は結果画面に残し、準備状態の要約と相互移動を設ける。両画面で最新の準備状態を取得し、旧応答破棄・版照合・取得中／失敗時の新規計算停止を維持する。

管理者の公開済み個人別勤務と固定解除をモーダルへ移す。月間表・日別配置のスタッフ名から対象者の1か月を開き、表示中の案／公開済み勤務を切り替える。計算案がない場合も公開版の名前から開ける。日付順に出退勤・休憩・勤務時間・取消・保存済みの業務／担当区分を表示し、記録なしと休日を区別する。現在の公開版だけ固定解除でき、過去公開版は閲覧のみ。選択IDはクリック時に確定する。背景の未保存編集を保ち、モーダル内の固定解除には独立した未保存・処理中・応答未確認の保護を適用する。一般スタッフ本人のシフト表示は維持する。

入力比較の常設カードを外し、古い案の見出し右横のinfoからホバー・タップ・キーボードで開く。初回表示時に取得し、同じ対象・版では比較の取得済みページを再利用する。版変更では無効化し、50件ごとの追加取得・比較不能・版競合・再読込を維持する。非同期操作で一時的にボタンが無効になっても閉じず、Escape・外側操作・閉じるボタンで閉じられる。古い案の警告と公開制御は同じ判定を使う。結果が残らないSTALEジョブでも凍結入力があれば比較できる。

ジョブ状態と試行番号・古い案の説明を連結する表示を廃止する。通常表示から試行番号を外し、古い案には「この案には最新の変更が反映されていません。最新条件で再計算してください。」と表示する。計算完了を公開済みや最新条件での有効性と同一視しない。

再検証の履歴と証明は別々の取得状態・エラー・再読込を持つ。対象キーごとの置換で管理し、旧公開版・旧検証IDの遅延応答を捨てる。表示は公開版ごとに固定した領域で行い、APIの重複IDは取得失敗として扱う。同内容の異なる検証IDは履歴として保持する。DBの履歴や証明を削除して重複表示を隠さない。

## 互換性と検証

既存API・DB・Container・ソルバーは変更しない。モーダルには既存alert-dialogの依存として使用中の`@radix-ui/react-dialog` 1.3.1を明示依存として追加する。ローカルの架空APIと実製品bundleを使うブラウザー試験で、表示・読取競合・固定解除再送・24回の定期更新を検証する。これは実D1／R2・認証・実ソルバー・Cloudflareの受入とは分離する。

実行結果と制約（過去の私有資料・公開対象外）。既存のADR 0123／0124／0127、入力比較の従来表示より本決定を優先する。
