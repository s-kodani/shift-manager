# ADR 0020：勤務取消の候補を現在の条件で独立検証する

2026-10-11。WP-08の承認・取消確定に必要な先行工程。Q69、Q84、Q96〜97、Q121、Q124、Q128〜131を参照する。確定した製品仕様は変更しない。

## 判断と実装

担当管理者が現在の公開勤務を基に取消候補を作り、既存Containerの独立チェッカーへ渡す。候補の入力と配置はサーバーで構築し、画面から配置・検証証明を受け取らない。受付の版、現在公開版、企業入力版、カレンダー、現在の明示固定・解除、所属と管理権限を照合する。対象日の明示固定が一つでも残る場合は先に解除を求める。

時間は整数分の半開区間で扱う。既存取消と今回取消を和集合にし、休憩との重複控除を避ける。元の勤務パターン・出退勤・休憩時刻・固定／自動種別を保ち、候補の取消区間と勤務分を更新する。重なる研修・会議から対象スタッフの全参加だけを候補上で解除し、他の参加者を維持する。残る役割区間と許可済み勤務不可例外は分単位で切り出す。新しい例外・待機・担当業務を自動で作らない。

候補の公開後維持基準を明示して独立チェッカーへ渡し、最低勤務量、休憩、未割当、準備・継続、取消後の希望などを検査する。元の計算ジョブが取消候補を計算したことにはしない。入力・配置のSHA-256と元公開証跡のSHA-256、各版を結果へ結び付ける。今回の結果は常に`NOT_COMMITTED`で、受付・公開勤務・参加登録・本人通知を確定更新しない。

通常計算・公開再検証・下書き検証と同じチームDOの排他・永続フェンスを共有する。チェック応答後とプロセス停止確認後にも入力・公開版・権限を再確認する。停止未確認では成功を返さず、フェンスを保持し、次の処理は旧プロセス停止を確認してから開始する。RPCの既知の業務エラーは明示的なJSON envelopeで渡し、競合409・権限失効403を保持する。Container障害・停止失敗を業務成功へ変換しない。

## 確認中の仕様の組み合わせ

半日取消に重なる研修・会議の全参加を解除すると、取消後に残る勤務内に担当業務のない時間が生じることがある。Q96〜97の即時反映・参加解除とQ124の未割当禁止の両立方法についてユーザーへ確認中。管理者が残る業務配置も確認して同時確定する案と、業務配置を用意するまで取消確定を止める案の選択を求めている。仮検証はこの状態を`WAITING`として検出する。承認・取消確定を実装済みとは扱わず、待機を許可する解釈へ変更しない。

## 実施結果・残る作業

実施記録（過去の私有資料・公開対象外）で、制御checkerによるD1／R2／DO試験、実Dockerの独立チェック、実画面と未実施事項を分ける。既存のWorkers・Containers構成と依存版を使い、新たな技術の採用や性能達成を宣言しない。

次は承認・取消確定時の独立再検証と、公開勤務・参加解除・履歴・通知・版の原子同期。仮確認の証明を後日の確定へ流用しない。取消の由来と証明を親公開版・原計算ジョブから区別し、再配置とその公開は別の管理者操作として実装する。Cloudflare配備、実端末、101／500人、復旧と現場受入は未実施。
